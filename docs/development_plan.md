# 开发计划

## 1. 当前阶段

当前处于文档设计阶段。

当前阶段只维护 `docs/`：

- 不创建 `backend/`。
- 不创建 `frontend/`。
- 不写业务代码。
- 不初始化依赖。

## 2. MVP 阶段划分

### 2.1 阶段一：基础闭环

目标：跑通“钉钉登录 + 单文件问答”。

范围：

- 初始化后端工程。
- 初始化前端工程。
- Docker Compose 启动后端、PostgreSQL、Redis。
- 前端通过宿主机 Vite 启动。
- 实现健康检查。
- 实现数据库 migration。
- 实现钉钉登录。
- 实现 JWT 鉴权。
- 实现基础聊天页面。
- 实现文件上传。
- 实现文件解析。
- 实现 chunk 和 embedding 入库。
- 实现基于单文件的问答。

验收：

- 用户可通过钉钉登录。
- 用户可上传一个文件。
- 文件解析后状态为 `ready`。
- 用户可围绕该文件提问。
- 后端检索时按 `file_id` 过滤。

### 2.2 阶段二：PPT 生成

目标：基于已上传文件生成 PPT。

范围：

- 设计并实现 `ppt_jobs`。
- 创建 PPT 生成任务。
- 使用 BackgroundTasks 执行任务。
- 任务状态持久化到数据库。
- 前端轮询任务状态。
- 下载生成结果。

验收：

- 用户可基于自己的文件创建 PPT 任务。
- 任务状态可查询。
- 生成成功后可下载 PPT。
- 失败时可看到错误信息。

### 2.3 阶段三：稳定性补强

目标：修复 MVP 使用中的明显问题。

范围：

- 错误处理。
- 日志完善。
- 文件大小和格式限制。
- 基础测试。
- API 错误码整理。
- 前后端联调问题修复。

不包含：

- Celery。
- OSS / MinIO。
- 企业知识库。
- 多模型切换。

## 3. 第一周建议计划

### Day 1：工程初始化

前置条件：

- Git 已安装。
- Docker Desktop 已安装。
- Claude API Key 已准备。
- 钉钉应用凭证已准备。

任务：

- 创建 backend 工程结构。
- 创建 frontend 工程结构。
- 创建 Docker Compose。
- 创建 `.env.example`。
- 创建健康检查接口。

验收：

- 后端容器可启动。
- PostgreSQL 可连接。
- Redis 可连接。
- `GET /health` 返回正常。

### Day 2：数据库基础

任务：

- 配置 SQLAlchemy。
- 配置 Alembic。
- 创建 `users` migration。
- 创建后续核心表 migration。

验收：

- migration 可执行。
- 数据库中可看到核心表。

### Day 3：钉钉登录

任务：

- 实现钉钉登录 API。
- 实现用户创建或更新。
- 实现 JWT 签发。
- 实现 `/api/v1/auth/me`。

验收：

- 可通过钉钉调试工具完成登录。
- 可拿到 JWT。
- JWT 可访问受保护接口。

### Day 4：前端登录与聊天框架

任务：

- 初始化 React + Vite。
- 实现登录入口。
- 保存 JWT。
- 实现聊天页面框架。

验收：

- 登录成功后进入聊天页面。
- 页面显示新会话入口。

### Day 5：文件上传与解析

任务：

- 实现文件上传 API。
- 实现本地存储。
- 实现异步文件解析（BackgroundTask）。
- 实现首批 Parser。
- 写入 `files` 和 `file_chunks`。

验收：

- 用户可上传文件。
- 文件状态可变为 `ready`。
- chunk 可入库。

## 4. 第二周建议计划

### Day 6-7：单文件问答

任务：

- 实现会话创建。
- 实现消息发送。
- 实现按 `file_id` 检索 chunk。
- 调用 Claude API 生成回答。
- 保存聊天记录。

验收：

- 用户可围绕指定文件问答。
- 不能访问其他用户文件内容。

### Day 8-9：PPT 任务

任务：

- 实现 `ppt_jobs`。
- 实现 PPT 任务创建。
- 实现 BackgroundTasks 执行。
- 实现状态查询和下载。

验收：

- 任务状态可持久化。
- 成功后可下载 PPT。

### Day 10：联调与收敛

任务：

- 修复前后端联调问题。
- 补充 happy path 测试。
- 整理错误码。
- 更新文档。

验收：

- MVP 主链路可演示。

## 5. 测试策略

一期测试重点：

- 每个核心 API 至少一个 happy path 集成测试。
- Service 层 mock 外部依赖。
- LLM、钉钉、文件存储不在单元测试中真实调用。

优先测试：

- 钉钉登录用户创建。
- 文件上传权限。
- 文件问答按 `file_id` 检索。
- PPT 任务状态流转。

## 6. 明确不做

开发过程中不要引入：

- 密码注册。
- Celery。
- MinIO / OSS。
- 多 Provider。
- 全局知识库。
- 多文件联合问答。
- 微服务。
- 微前端。
- Redux。

## 7. 说明

所有此前待确认项已在 `mvp_decision.md` 中固化，此处不再保留为开放问题。

已落地决策要点：
- 首批文件格式：TXT、PDF、DOCX，上限 20MB。
- Claude 模型版本通过环境变量配置。
- embedding：BGE-M3（本地部署），1024 维。
- PPT 生成库：python-pptx，固定模板。
