# v1.5.6 Local Process Control Report

## 1. 工程效果

本阶段增强了 Windows 本地启动、停止和检查脚本，让本地调试更稳定。脚本现在明确只处理固定端口上的 `LISTENING` 进程，并忽略 `TIME_WAIT`。启动后会读取 `/health/config`，输出当前后端实际配置摘要。

本阶段没有修改业务代码，没有修改 RAG 主链路，也没有修改数据库结构。

## 2. 脚本职责变化

### scripts/check-local.ps1

新增能力：

- 检查 8000 和 5173 是否存在 `LISTENING` 进程。
- 输出占用端口的 PID 和进程名。
- 明确说明 `TIME_WAIT` 会被忽略。

作用：

- 启动前快速判断端口是否真的被服务占用。

### scripts/stop-local.ps1

新增能力：

- 只停止固定端口上 `LISTENING` 状态的 PID。
- 停止前输出端口、PID 和进程名。
- 停止后再次检查端口是否释放。
- 如果仍有监听进程，输出剩余 PID。

作用：

- 避免按 `python` 或 `node` 进程名批量杀进程。
- 降低误杀其它开发任务的风险。

### scripts/start-local.ps1

新增能力：

- 启动前检查 8000 和 5173 是否已有 `LISTENING`。
- 如果端口被占用，直接提示先运行 `stop-local.ps1`，不盲目启动。
- 后端启动后请求 `/health/config`。
- 输出：
  - `llm_model`
  - `embedding_model`
  - `embedding_dimension`
  - `access_control.mode`

作用：

- 启动后马上确认当前后端是否读取了预期 `.env`。

## 3. 如何避免旧后端进程导致配置不生效

过去的问题是：

```text
旧后端仍占用 8000
-> 前端默认请求 8000
-> 新 .env 没有被旧进程读取
-> 新上传文件仍生成 mock embedding
```

现在的流程变为：

```text
check-local.ps1
-> 明确看到 8000 是否有 LISTENING PID
-> stop-local.ps1 只停止这个 PID
-> start-local.ps1 启动前再次确认端口空闲
-> 后端启动后读取 /health/config
-> 直接看到 embedding_model / embedding_dimension
```

这样可以更早发现“旧后端还在响应请求”的问题。

## 4. 它和 /health/config 如何配合

`/health/config` 提供当前后端进程实际读取到的非敏感配置。

`start-local.ps1` 在启动后自动调用该接口，并输出：

```text
llm_model
embedding_model
embedding_dimension
access_control.mode
```

如果输出仍然是：

```text
mock-embedding / 16
```

而 `.env` 已经配置了 `BAAI/bge-m3 / 1024`，说明当前启动的后端不是预期配置，或者 `.env` 未保存、环境变量被覆盖。

## 5. 仍不能解决的 Windows 权限问题

本阶段不能保证解决所有 Windows 进程问题。

仍可能遇到：

- 某些 PID 对当前 PowerShell 不可见。
- 某些进程需要管理员权限才能结束。
- `uvicorn --reload` 父子进程导致 PID 变化。
- `netstat` 短时间显示过期 PID。
- `TIME_WAIT` 残留显示较多，但它不代表服务仍在运行。

如果遇到权限问题，仍可能需要：

- 手动关闭对应 PowerShell 窗口。
- 使用管理员 PowerShell。
- 改用备用端口，例如 8001。
