# v1.2.1 数据库表与 ChatRepository 基础报告

## 1. 工程效果

v1.2.1 完成了持久会话的后端数据底座，但暂不接入前端，也暂不修改普通聊天和 RAG 主链路。

本阶段新增了：

- `chat_sessions` 表：保存会话基础信息。
- `chat_messages` 表：保存会话消息。
- `ChatRepository`：封装会话和消息的数据库读写。

完成后，后端已经具备以下基础能力：

- 创建会话。
- 查询会话列表。
- 查询单个会话。
- 删除会话。
- 写入消息。
- 查询某个会话下的消息。
- 删除会话时同步删除该会话的全部消息。

## 2. 修改文件职责

### `backend/app/db/models.py`

新增 `ChatSessionRecord`：

- `id`：会话 ID。
- `title`：会话标题，默认“新对话”。
- `mode`：会话模式，MVP 阶段默认 `chat`。
- `bound_file_id`：当前会话绑定的单个 RAG 文件 ID，后续接入。
- `created_at` / `updated_at`：会话创建和更新时间。

新增 `ChatMessageRecord`：

- `id`：消息 ID。
- `session_id`：所属会话 ID。
- `role`：消息角色，例如 `user` 或 `assistant`。
- `content`：消息正文。
- `metadata_json`：消息扩展信息，后续用于保存 RAG `used_chunks` 等数据。
- `created_at`：消息创建时间。

### `backend/app/repositories/chat_repository.py`

新增 `ChatRepository`，职责是纯数据库读写：

- `create_session()`：创建一条会话记录。
- `list_sessions()`：按更新时间倒序返回会话列表。
- `get_session()`：按 ID 查询单个会话。
- `delete_session()`：删除会话，并同步删除该会话下的所有消息。
- `create_message()`：创建消息，并更新所属会话的 `updated_at`。
- `list_messages()`：按创建时间正序返回某个会话下的消息。
- `_touch_session()`：内部方法，用于在写入消息时刷新会话更新时间。

### `docs/status.md`

同步当前状态到 v1.2.1：

- 标记 `chat_sessions` 和 `chat_messages` 表已完成。
- 标记 `ChatRepository` 基础能力已完成。

## 4. 为什么当前阶段不接入聊天 API

本阶段只做数据库表和 Repository，是为了先稳定“数据怎么存、怎么查、怎么删”。

如果同时改 API、前端、聊天服务和 RAG 服务，问题会混在一起：

- 不容易判断是数据库问题、接口问题还是前端状态问题。
- 普通聊天和 RAG 主链路会承担不必要风险。
- 后续排查会话恢复时会缺少清晰边界。

因此 v1.2.1 只完成后端持久化底座。下一阶段再引入 `ConversationService` 和会话 API，会更稳。

## 5. 后续如何接入 ConversationService

下一阶段建议新增 `ConversationService`，负责把现有聊天和 RAG 能力与 `ChatRepository` 连接起来。

普通聊天后续调用链：

```text
POST /api/v1/chat
-> ConversationService.answer_and_persist_chat()
-> ChatService.answer()
-> ChatRepository.create_message(user)
-> ChatRepository.create_message(assistant)
```

RAG 问答后续调用链：

```text
POST /api/v1/files/{file_id}/ask
-> ConversationService.ask_file_and_persist()
-> RagService.ask_file()
-> ChatRepository.create_message(user)
-> ChatRepository.create_message(assistant with metadata_json)
```

会话文件绑定后续调用链：

```text
PATCH /api/v1/chat/sessions/{session_id}/file
-> ConversationService.bind_file()
-> ChatRepository 更新 chat_sessions.bound_file_id
```
