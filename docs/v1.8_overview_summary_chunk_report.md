# v1.8.6 Overview Retrieval and Summary Chunk 报告

## 1. 本阶段工程效果

本阶段专门改善宽泛总览类问题，例如：

- 当前完成了哪些核心能力？
- 项目目前进展如何？
- 北辰agent 能做什么？

新增能力：

- ChunkService 为结构化大章节生成 `section_summary` chunk。
- chunk metadata 增加 `chunk_type`。
- `chunk_type` 支持 `normal` 和 `section_summary`。
- VectorStore 保存 `chunk_type`。
- RetrievalResult 返回 `chunk_type`。
- RetrievalService 增加 `overview` intent。
- overview 问题会对 `section_summary` 和总览章节加分。
- overview 问题会降低配置类、RAG 指标类和限制风险类噪声片段。
- 前端文件中心和聊天侧引用片段展示 chunk type。

本阶段没有新增 AI 业务功能，没有修改数据库结构，没有引入 pgvector、rerank、多文件 RAG，也没有调用 LLM 生成摘要。

## 3. summary chunk 生成规则

summary chunk 不调用 LLM，而是由规则生成。

生成内容包括：

1. 章节标题。
2. 子标题列表。
3. 前若干条关键句。

示例：

```text
Section Summary: 当前已完成功能
Subsections:
- 普通 AI 聊天
- 文件上传与自动处理
- 单文件 RAG 问答
Key lines:
- 用户可以进行基础连续追问。
- 用户可以上传 TXT、DOCX、文本型 PDF 文件。
```

它的目的不是替代原文，而是给 overview 问题提供更稳定的召回入口。

## 4. chunk_type 如何参与检索

当前支持：

- `normal`：原始正文 chunk。
- `section_summary`：规则生成的章节总览 chunk。

当 query intent 是 `overview` 时：

- `section_summary` 会获得额外 boost。
- 当前已完成功能、项目背景、试运行范围等总览章节会获得 boost。
- 当前配置、RAG 质量指标、限制风险等细节或噪声章节会被 penalty。

普通事实型问题仍然可以命中 normal chunk，不会被 summary chunk 替代。

## 5. overview intent 识别规则

当前使用规则识别，不调用 LLM。

命中以下表达时，倾向识别为 overview：

- 总结
- 概览
- 进展
- 现状
- 核心能力
- 完成了哪些
- 有哪些功能
- 能做什么
- 可以做什么

## 6. 为什么不调用 LLM 生成摘要

本阶段不调用 LLM 生成摘要，原因是：

- 避免新增成本。
- 避免重新索引变慢。
- 避免引入摘要是否准确的新风险。
- 保持 MVP 简单和可解释。

当前的 section_summary 是检索辅助材料，不是最终答案。
