# v1.7.2 Runtime Backup and Restore 报告

## 1. 本阶段工程效果

本阶段完成 v1.7.2 Runtime Backup and Restore。

本次没有新增 AI 业务功能，没有修改 RAG 主链路，没有修改数据库结构。主要目标是为已经公网部署验证的北辰agent 增加最小服务器运行时数据备份和恢复能力。

新增后，项目在 Ubuntu VPS 上可以通过脚本模板备份：

- SQLite 数据库目录。
- 原始上传文件目录。
- 本地 JSON VectorStore 目录。
- 可选日志目录。

同时提供恢复脚本模板，用于在部署失误、数据损坏或误操作后恢复 runtime 数据。

## 2. 新增文件职责

### `deploy/scripts/backup-runtime.sh.example`

职责：

- 面向 Ubuntu VPS 的 runtime 数据备份脚本模板。
- 默认备份 `/opt/beichen-agent/runtime/data`。
- 默认备份 `/opt/beichen-agent/runtime/uploads`。
- 默认备份 `/opt/beichen-agent/runtime/vector_store`。
- 可通过 `--include-logs` 备份 `/opt/beichen-agent/runtime/logs`。
- 将备份压缩为带时间戳的 `.tar.gz` 文件。
- 输出到 `/opt/beichen-agent/backups`。

安全边界：

- 不打印 API Key。
- 不打印邀请码。
- 不删除任何数据。
- 不提交真实备份文件。

### `deploy/scripts/restore-runtime.sh.example`

职责：

- 面向 Ubuntu VPS 的 runtime 数据恢复脚本模板。
- 需要用户显式传入备份文件路径。
- 明确提示恢复会覆盖当前 runtime 数据。
- 要求用户输入 `RESTORE` 才继续。
- 停止 `beichen-agent` systemd 服务。
- 尽量在恢复前创建一次 pre-restore 安全备份。
- 解压备份到 `/opt/beichen-agent/runtime`。
- 修正 runtime 文件权限为 `www-data:www-data`。
- 恢复后启动 `beichen-agent` 服务。
- 提示运行 `/health` 和 `/health/config` 检查。

安全边界：

- 不恢复真实 `.env`。
- 不自动删除 backups 目录。
- 不自动下载远程备份。
- 不执行破坏性 Git 命令。

## 4. 备份对象

必须备份：

```text
/opt/beichen-agent/runtime/data
/opt/beichen-agent/runtime/uploads
/opt/beichen-agent/runtime/vector_store
```

含义：

- `data`：SQLite 数据库，保存文件元数据、处理状态、会话、消息和匿名 client_id 归属。
- `uploads`：用户上传的原始文件。
- `vector_store`：本地 JSON 索引，包含 chunks 和 embeddings。

这三个目录必须一起备份。只备份其中一部分会造成数据不一致。

可选备份：

```text
/opt/beichen-agent/runtime/logs
```

日志用于排查问题，不是核心业务数据。

## 5. 恢复流程

推荐恢复流程：

1. SSH 登录服务器。
2. 确认要恢复的备份文件。
3. 进入项目目录：

```bash
cd /opt/beichen-agent/app
```

4. 执行恢复脚本：

```bash
sudo bash deploy/scripts/restore-runtime.sh.example /opt/beichen-agent/backups/beichen-runtime-YYYYMMDD-HHMMSS.tar.gz
```

5. 根据提示输入：

```text
RESTORE
```

6. 脚本会停止后端服务、恢复 runtime、修正权限并重新启动服务。

7. 恢复后检查：

```bash
sudo systemctl status beichen-agent
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/health/config
```

8. 在网页端检查：

- 文件列表是否存在。
- 会话列表是否存在。
- 历史消息是否能恢复。
- indexed 文件是否还能 RAG 问答。

## 6. 部署前如何使用备份

每次服务器更新前建议先运行：

```bash
cd /opt/beichen-agent/app
sudo bash deploy/scripts/backup-runtime.sh.example
```

如果需要同时保存日志：

```bash
sudo bash deploy/scripts/backup-runtime.sh.example --include-logs
```

然后再执行：

```bash
sudo -u www-data git pull
cd backend
sudo -u www-data /opt/beichen-agent/venv/bin/pip install -r requirements.txt
sudo -u www-data /opt/beichen-agent/venv/bin/python -m compileall app
cd ../frontend
sudo -u www-data npm install
sudo -u www-data npm run build
sudo systemctl restart beichen-agent
sudo nginx -t
sudo systemctl reload nginx
```

部署后验证：

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/health/config
```

## 7. 当前方案限制

当前方案仍是 MVP 级别。

限制：

- 不是自动定时备份。
- 不是异地备份。
- 不加密备份包。
- 不上传对象存储。
- 不支持选择性恢复单个用户、单个文件或单个会话。
- 不处理 PostgreSQL 或 pgvector。
- 恢复会覆盖当前 runtime 数据。

当前阶段可以接受的原因：

- 项目仍处于 1-5 人可信试用阶段。
- 数据量较小。
- 目标是降低部署误操作风险，而不是建设完整运维平台。

后续可升级方向：

- cron 定时备份。
- 备份包加密。
- 上传到对象存储。
- PostgreSQL 后使用 `pg_dump`。
- pgvector 后设计向量索引备份策略。
