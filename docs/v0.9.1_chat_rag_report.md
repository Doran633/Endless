# v0.9.1 Chat-side RAG QA 实现报告

## 1. 工程效果

v0.9.1 将 v0.9.0 的单文件 RAG 问答能力接入聊天主流程。

当前效果：

```text
聊天框上传文件
  -> 自动上传
  -> 自动解析
  -> 自动切块
  -> 自动 mock 向量化
  -> 自动保存本地 VectorStore
  -> 当前会话绑定最近一个 indexed 文件
  -> 用户继续在聊天框提问
  -> 调用 /api/v1/files/{file_id}/ask
  -> AI 回答进入聊天消息流
  -> 消息中展示引用 chunks 摘要
```

如果当前没有 indexed 文件，聊天仍保持原有普通 LLM 调用：

```text
用户消息 -> /api/v1/chat -> 普通 AI 回答
```

如果文件仍在处理中，用户提问时不会降级成普通聊天，而是提示等待索引完成。

## 2. 修改文件职责

### `frontend/src/stores/fileStore.ts`

新增状态：

- `activeRagFileId`
- `activeRagFileName`
- `clearActiveRagFile()`

职责：

- 在聊天侧文件自动处理完成并保存索引后，记录最近一个 indexed 文件。
- 新文件开始处理时清空旧的 active RAG 文件，避免误用旧文档回答。
- 文件中心手动保存索引后，也可以设置当前 active RAG 文件。
- 删除当前 active 文件时同步清空绑定状态。

设计原因：

- 文件处理状态本来就在 `fileStore`，active RAG 文件也属于文件上下文。
- `chatStore` 只读取这个状态来决定调用普通聊天还是文件问答。

### `frontend/src/stores/chatStore.ts`

新增聊天分流逻辑：

```text
sendMessage()
  -> if file is ingesting
       append waiting message
  -> else if current session has indexed file
       call askFile()
  -> else
       call sendChatMessage()
```

职责：

- 保持用户消息写入聊天流。
- 通过 `sessionRagFiles` 记录“当前会话 -> 最近 indexed 文件”的绑定。
- 根据当前会话文件状态选择 `/api/v1/chat` 或 `/api/v1/files/{file_id}/ask`。
- 把 RAG answer 写入 assistant 消息。
- 把引用 chunks 摘要写入 message metadata。

设计原因：

- 不修改后端 RAG 主链路。
- 不把文件内容塞进普通聊天 prompt。
- 避免文件未处理完成时生成“假文件问答”。
- 避免 A 会话上传的文件影响 B 会话。

### `frontend/src/components/ChatInput.tsx`

新增：

- 当前 active 文件提示。
- 文件处理中状态提示。
- “清除当前文件”按钮。
- placeholder 根据当前模式切换。

职责：

- 让用户知道当前提问是否会基于文件。
- 让用户可以清除当前文件，恢复普通聊天。
- 保留原聊天框上传文件入口。

### `frontend/src/components/MessageBubble.tsx`

新增：

- RAG 引用 chunks 摘要展示。

职责：

- 在 AI 回答下方展示引用文件名、chunk_index、score 和内容预览。
- 帮助用户核对答案依据。

### `frontend/src/types/index.ts`

扩展 `Message.metadata`：

- `rag_file_id`
- `rag_file_name`
- `used_chunks`

职责：

- 为聊天消息保存 RAG 引用信息。
- 后续接数据库时可直接持久化消息 metadata。

### `docs/status.md`

同步当前版本到 `v0.9.1`。

### `docs/v0.9.1_chat_rag_report.md`

记录本阶段实现效果、调用链路、错误处理和测试方法。

## 3. 聊天侧 RAG 调用链路

### 3.1 文件上传处理链路

```text
ChatInput
  -> fileStore.ingestFile(file)
  -> uploadFile()
  -> POST /api/v1/files
  -> parseFile()
  -> POST /api/v1/files/{file_id}/parse
  -> chunkFile()
  -> POST /api/v1/files/{file_id}/chunks
  -> embedFile()
  -> POST /api/v1/files/{file_id}/embeddings
  -> storeFileVectors()
  -> POST /api/v1/files/{file_id}/vector-store
  -> fileStore activeRagFileId = file_id
  -> chatStore sessionRagFiles[currentSessionId] = file_id
```

### 3.2 文件问答链路

```text
ChatInput
  -> chatStore.sendMessage(query)
  -> read chatStore.sessionRagFiles[currentSessionId]
  -> askFile(file_id, query, topK=3)
  -> POST /api/v1/files/{file_id}/ask
  -> RagService
  -> RetrievalService
  -> LLMProvider
  -> AskFileResponse
  -> assistant message
  -> MessageBubble renders answer + used_chunks
```

### 3.3 普通聊天链路

```text
ChatInput
  -> chatStore.sendMessage(message)
  -> no current session RAG file
  -> sendChatMessage(message)
  -> POST /api/v1/chat
  -> assistant message
```

## 4. 错误处理方式

### 文件处理中提问

行为：

- 不调用 `/api/v1/chat`。
- 不调用 `/api/v1/files/{file_id}/ask`。
- 直接在消息流中提示：

```text
文件还在处理中，请稍等完成索引后再基于该文件提问。
```

原因：

- 避免用户以为系统已经基于文件回答。

### 文件处理失败

行为：

- `fileStore.ingestFile()` 设置 `ingestion.status = failed`。
- 不设置 `activeRagFileId`。
- 用户继续提问时走普通聊天。

### RAG 问答失败

行为：

- assistant 消息展示错误信息。
- 不清空 active 文件，允许用户稍后重试。

### 清除当前文件

行为：

- 用户点击清除按钮。
- 清空 `activeRagFileId` 和 `activeRagFileName`。
- 后续问题恢复普通聊天。

## 5. 当前限制

- 当前仅绑定最近一个 indexed 文件。
- 当前 active 文件状态只保存在前端内存中，刷新页面会丢失。
- 当前没有多文件选择。
- 当前没有历史对话检索。
- 当前 embedding 仍是 mock，RAG 质量主要验证工程链路，不代表真实语义效果。
- 当前引用 chunks 只展示摘要，不支持高亮和展开全文。

## 6. 测试方法

基础验证：

```text
cd backend
python -m compileall app
```

```text
cd frontend
npm exec tsc -- --noEmit
```

浏览器验证：

1. 打开 `http://127.0.0.1:5173/`。
2. 不上传文件，直接提问，确认普通聊天可用。
3. 在聊天框上传 TXT / DOCX / PDF。
4. 等待状态显示文件已准备好。
5. 在聊天框输入：

```text
这个文档主要讲了什么？
```

6. 确认回答显示在聊天消息流中。
7. 确认回答下方出现引用 chunks 摘要。
8. 点击清除当前文件。
9. 再次提问，确认恢复普通聊天。

范围检查：

- 没有新增后端 RAG 主链路。
- 没有新增数据库。
- 没有新增 pgvector。
- 没有实现多文件 RAG。
- 没有实现历史对话检索。
- 没有实现 Agent。
