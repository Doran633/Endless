# v0.6.1 聊天侧文件接入体验优化计划

> 本计划用于 v0.6.1 开发阶段。目标是在不实现 RAG、不实现文件问答、不引入向量数据库的前提下，把文件上传入口前移到聊天窗口，并自动完成上传、解析、切块和 mock 向量化。

## 1. 当前问题

当前项目已经完成 v0.6 Embedding 抽象与调用闭环：

```text
文件上传
  -> 文档解析
  -> 文本切块
  -> mock 向量化
```

但当前交互仍然偏工程调试流程：

- 用户需要进入文件中心。
- 用户需要手动点击“解析”。
- 用户需要手动点击“切块”。
- 用户需要手动点击“向量化”。
- 聊天窗口没有文件上传入口。

这对开发调试是清晰的，但对真实用户不够自然。普通用户上传文件的目的通常不是观察解析、切块、向量化三个技术步骤，而是希望系统“准备好这个文件，后续可以用来问答”。

因此 v0.6.1 的核心问题不是补后端能力，而是优化前端使用路径。

## 2. 产品体验判断

建议在聊天窗口输入区增加一个轻量文件上传入口。

用户行为应简化为：

```text
在聊天窗口选择文件
  -> 系统自动上传
  -> 系统自动解析
  -> 系统自动切块
  -> 系统自动向量化
  -> 展示“文件已准备”
```

这符合 AI 助手类产品的直觉：文件上传应该属于对话上下文准备动作，而不是一个必须单独进入后台管理页面完成的工程操作。

但 v0.6.1 不应完全隐藏处理状态。原因是当前还没有持久化、VectorStore 和 RAG，一旦处理失败，用户需要知道失败发生在哪一步。因此聊天区应该展示简洁状态，而文件中心继续保留详细状态。

推荐体验：

```text
正在上传...
正在解析...
正在切块...
正在向量化...
文件已准备
```

## 4. 前端交互设计

聊天输入区增加文件上传按钮，建议放在输入框左侧或下方工具区。

交互原则：

- 上传按钮使用图标按钮，例如附件图标。
- 不使用大面积上传卡片，避免破坏当前简洁 UI。
- 用户选择文件后立即开始自动处理。
- 处理期间按钮进入 loading 或 disabled 状态。
- 同一时间先只允许处理一个文件，降低 MVP 复杂度。
- 处理完成后显示简短结果。

聊天区提示建议：

```text
已上传：xxx.pdf
正在解析...
正在切块...
正在向量化...
文件已准备，后续 RAG 阶段可用于问答
```

注意：最后一句必须避免暗示“现在已经可以文件问答”。

## 5. 自动处理流程

v0.6.1 不新增后端编排接口，前端直接串联现有 API。

流程如下：

```text
ChatInput
  -> useFileStore.ingestFile(file)
  -> uploadFileApi(file)
  -> parseFileApi(file_id, extension)
  -> chunkFileApi(file_id, extension)
  -> embedFileApi(file_id, extension)
  -> 更新 files 状态
  -> 聊天区显示处理完成
```

为什么暂时由前端编排：

- 当前没有数据库和任务状态表。
- 当前没有后台 job 系统。
- 当前每一步已有独立 API，可复用。
- v0.6.1 目标是体验优化，不是后端架构升级。

后续进入持久化或任务队列阶段后，可以把该流程迁移到后端：

```text
POST /api/v1/files/ingest
  -> FileService
  -> DocumentParserService
  -> ChunkService
  -> EmbeddingService
  -> VectorStore
```

## 6. 状态展示方案

建议新增聊天侧临时处理状态，不污染聊天消息历史。

状态枚举建议：

```text
idle
uploading
parsing
chunking
embedding
completed
failed
```

展示字段建议：

- `fileName`
- `status`
- `errorMessage`
- `chunkCount`
- `embeddingCount`
- `embeddingDimension`

前端显示规则：

- `uploading`：正在上传文件
- `parsing`：正在解析文档
- `chunking`：正在切分文本
- `embedding`：正在生成向量
- `completed`：文件已准备
- `failed`：处理失败，显示失败原因

文件中心状态仍使用已有 `FileItem.status`：

```text
uploaded
processing
ready
chunked
embedded
failed
```

聊天侧状态用于用户体验，文件中心状态用于文件管理和调试。

## 7. 与文件中心的关系

文件中心继续保留，且不降级为无用页面。

聊天侧入口负责：

- 快速上传。
- 自动处理。
- 展示简洁状态。

文件中心负责：

- 查看已上传文件。
- 查看解析预览。
- 查看 chunk 预览。
- 查看 embedding 预览。
- 后续扩展删除、重新处理、文件列表刷新等管理功能。

二者关系：

```text
聊天区：高频入口
文件中心：管理和调试入口
```

这比完全移除文件中心更稳妥，因为当前项目仍处在 RAG 前置工程阶段，需要保留可观察性。

## 8. 不做范围

v0.6.1 明确不做：

- 不实现 RAG。
- 不实现文件问答。
- 不实现向量数据库。
- 不实现真实 embedding API。
- 不保存 vectors 到数据库。
- 不保存 chunks 到数据库。
- 不把文件内容直接拼进聊天 prompt。
- 不让聊天回答自动引用上传文件。
- 不新增复杂后端编排接口。
- 不实现任务队列。
- 不实现多文件并发处理。
- 不实现企业权限。
- 不实现 Agent Workflow。

尤其需要避免临时方案：

```text
上传文件后把全文塞进 prompt 让 LLM 回答
```

这种做法短期能看到文件问答效果，但会绕过真实 RAG 工程路线，并造成上下文长度、成本、可解释性和后续重构问题。

## 9. 风险和技术债

### 9.1 前端编排会产生重复逻辑

文件中心已经有手动 `parseFile`、`chunkFile`、`embedFile` 动作。聊天侧如果再写一套串联逻辑，可能产生重复。

控制方式：

- 把自动处理封装在 `fileStore.ingestFile()`。
- `ChatInput` 只调用 store action，不直接关心四个 API 细节。

### 9.2 当前没有持久化

刷新页面后，前端状态仍会丢失。

这是当前 MVP 阶段可接受的技术债。后续 v0.7 或数据库阶段需要解决文件元数据、chunks 和 vectors 的持久化。

### 9.3 失败恢复能力有限

如果解析、切块或向量化中间失败，当前只能提示失败，不能从失败步骤继续。

MVP 处理方式：

- 显示失败原因。
- 允许用户重新上传或去文件中心重新触发。

### 9.4 处理时间可能变长

大文件会导致自动处理耗时变长。

MVP 处理方式：

- 保持按钮 loading。
- 展示当前阶段。
- 文件大小继续复用后端限制。

### 9.5 用户可能误解为已经支持文件问答

如果文案写成“可以开始问文件了”，会制造错误预期。

文案必须明确：

```text
文件已准备，后续 RAG 阶段可用于问答
```

而不是：

```text
你现在可以基于文件提问
```

## 10. 测试方案

### 10.1 前端类型检查

运行：

```text
npm exec tsc -- --noEmit
```

预期：

- TypeScript 类型检查通过。

### 10.2 后端回归检查

由于 v0.6.1 不计划修改后端，仍建议确认后端可用：

```text
python -m compileall app
```

预期：

- Python 编译检查通过。

### 10.3 浏览器手动验证

启动后端：

```text
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

启动前端：

```text
cd frontend
npm run dev -- --host 127.0.0.1 --port 5173
```

验证流程：

1. 打开聊天页面。
2. 在聊天输入区选择 TXT 文件。
3. 确认出现上传状态。
4. 确认状态依次进入解析、切块、向量化。
5. 确认最终显示文件已准备。
6. 打开文件中心。
7. 确认该文件状态为已向量化。
8. 确认可查看解析预览、chunk 预览和 embedding 预览。
9. 发送普通聊天消息，确认聊天仍然只走普通 LLM，不自动引用文件。

### 10.4 错误路径验证

建议验证：

- 上传不支持的文件类型。
- 上传空文件。
- 上传过大的文件。
- 后端未启动时上传。

预期：

- 前端展示清晰失败提示。
- 文件状态变为 failed 或不进入文件列表。
- 聊天功能不受影响。

## 11. 下一步关系

v0.6.1 完成后，项目状态会变成：

```text
用户体验上：文件可以从聊天区进入系统
工程链路上：文件可以自动完成 RAG 前置处理
能力边界上：仍未实现 RAG 问答
```

这会为 v0.7 做好产品入口准备。

建议 v0.7 再进入：

```text
VectorStore 抽象
  -> 保存 chunk + embedding
  -> 支持按 file_id 查询
  -> 为 RetrievalService 做准备
```
