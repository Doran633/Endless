# v0.4 文档解析报告

> 本报告记录 v0.4 最小文档解析闭环的实现结果。
> 本阶段不包含 RAG、Embedding、向量数据库、数据库、复杂任务队列、企业权限、Agent 或 PPT。

## 1. 本次完成内容

v0.4 已实现最小文档解析闭环：

```text
前端上传文件
  -> 前端点击“解析”
  -> POST /api/v1/files/{file_id}/parse
  -> DocumentParserService
  -> 从 backend/uploads/ 读取文件
  -> 提取纯文本
  -> 返回 text_preview 和 char_count
  -> 前端展示解析状态和文本预览
```

当前支持：

- TXT 解析。
- DOCX 段落文本解析。
- DOCX 基础表格单元格文本解析。
- 可复制文本型 PDF 解析实现。

当前不支持：

- 扫描件 PDF OCR。
- 图片文字识别。
- 复杂版式还原。
- RAG 问答。
- Embedding。
- 数据库持久化。

## 3. 当前调用链路

上传链路保持 v0.3 设计：

```text
FileCenter.handleUpload()
  -> fileStore.uploadFile()
  -> fileApi.uploadFile()
  -> POST /api/v1/files
  -> FileService
  -> backend/uploads/{file_id}.{extension}
```

解析链路：

```text
FileCenter.handleParse(file)
  -> fileStore.parseFile(file.id)
  -> fileApi.parseFile(file.id, file.extension)
  -> POST /api/v1/files/{file_id}/parse
  -> DocumentParserService.parse(file_id, extension)
  -> _parse_txt / _parse_docx / _parse_pdf
  -> ParsedFileResponse
  -> 前端状态更新为 ready
  -> 用户查看 text_preview
```

## 4. 设计原因

### 4.1 为什么新增 DocumentParserService

`FileService` 只负责上传和保存文件。

`DocumentParserService` 只负责读取文件并提取文本。

这样可以保持职责边界清晰：

```text
FileService
  -> 保存原文件

DocumentParserService
  -> 提取纯文本

未来 ChunkService
  -> 切分文本

未来 EmbeddingService
  -> 生成向量

未来 RagService
  -> 检索并组织 LLM 上下文
```

### 4.2 为什么解析接口需要传 extension

当前项目还没有数据库。

后端不能只通过 `file_id` 查询文件扩展名，所以 v0.4 暂时让前端传入 `extension`。

这是一个明确的 MVP 技术债。

后续引入数据库后，应改为：

```text
前端只传 file_id
  -> 后端通过 file_id 查询文件元数据
  -> 后端自行确定 extension 和 storage_path
```

### 4.3 为什么不在 v0.4 做 RAG

RAG 至少需要：

- 文档解析。
- 文本切块。
- Embedding。
- 向量存储。
- 检索。
- LLM 上下文拼接。

v0.4 只解决第一步“文档解析”，避免一次性把多个复杂模块耦合在一起。

## 6. 当前剩余问题

- 当前没有数据库，解析结果不会持久化。
- 页面刷新后，文件列表和解析结果不会从后端恢复。
- 解析接口暂时需要前端传 `extension`。
- PDF 只支持可复制文本，不支持扫描件 OCR。
- 解析结果只是文本预览，不是全文管理系统。
- 尚未建立后端自动化测试目录。
- RAG、Embedding、向量存储和 chunk 仍未实现。

## 7. 下一阶段 v0.5 建议

v0.5 建议进入文本切块阶段。

目标：

- 新增 `ChunkService`。
- 将解析出的全文切成固定大小 chunk。
- 保留 chunk 顺序。
- 返回 chunk 数量和 chunk 预览。
- 暂时仍不做 embedding。

建议链路：

```text
DocumentParserService
  -> Parsed text
  -> ChunkService
  -> chunks
  -> 后续 EmbeddingService
```

这样 v0.5 完成后，项目就具备进入 embedding 和向量检索的前置结构。
