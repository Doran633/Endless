# v1.5.1 Minimal Access Protection Report

## 1. 本次完成内容

本阶段完成了最小访问口令保护，为未来公网部署提供一层轻量防护。它的目标不是做正式登录系统，而是在部署后避免陌生人直接调用 `/api/v1/*` 接口并消耗你的 LLM / Embedding API Key。

## 2. 修改文件职责

- `backend/app/core/config.py`：新增 `APP_ACCESS_PASSWORD` 和 `APP_ACCESS_HEADER` 配置读取，并修正默认 `APP_NAME` 为 Beichen Agent。
- `backend/app/core/access_control.py`：新增访问保护中间件，只在配置了访问口令时校验 `/api/v1/*` 请求。
- `backend/app/main.py`：注册访问保护中间件，不改变原有 router 和 RAG 主链路。
- `backend/.env.example`：新增访问口令示例字段，不包含真实口令。
- `frontend/src/api/http.ts`：新增统一 `fetchWithAccess()`，从 `localStorage` 读取访问口令并自动附加请求头。
- `frontend/src/api/chatApi.ts`：聊天和会话 API 改为复用 `fetchWithAccess()`。
- `frontend/src/api/fileApi.ts`：文件、解析、切块、embedding、vector-store、retrieval、RAG API 改为复用 `fetchWithAccess()`。
- `frontend/src/components/LoginPage.tsx`：入口页新增访问口令输入，本地开发可留空。
- `frontend/src/components/Sidebar.tsx`：退出时清除本地访问口令，方便重新输入。
- `README.md`：新增最小访问保护配置说明。
- `docs/local_trial_guide.md`：补充本地试运行和可信任试用场景下的访问口令说明。
- `docs/troubleshooting.md`：补充 401 和请求头不一致排障说明。
- `docs/status.md`：同步当前阶段状态。

## 3. 访问保护调用链

前端入口页输入口令：

`LoginPage -> setAccessPassword() -> localStorage`

前端调用 API：

`chatApi/fileApi -> fetchWithAccess() -> X-Beichen-Access header -> /api/v1/*`

后端校验：

`FastAPI middleware -> access_control_middleware() -> settings.app_access_password -> allow / reject`

如果 `APP_ACCESS_PASSWORD` 为空，后端直接放行，适合本地开发。如果非空，只有携带正确请求头的 `/api/v1/*` 请求会被放行。

## 4. 为什么这不是正式登录系统

本阶段没有用户表、密码哈希、注册登录、session cookie、JWT refresh token、角色权限、多用户隔离或审计日志。它只是一个共享口令门禁，适合个人 MVP 的小范围部署前保护。

## 5. 部署配置方式

部署时在服务器的 `backend/.env` 中配置：

```env
APP_ACCESS_PASSWORD=请填写一个足够长的随机口令
APP_ACCESS_HEADER=X-Beichen-Access
```

前端默认会使用 `X-Beichen-Access` 请求头。如果未来修改请求头名，需要同时设置前端构建环境变量 `VITE_ACCESS_HEADER`。

## 6. 工程意义

这一步没有提升 AI 能力，但降低了公网试运行阶段的 API Key 滥用风险。它让项目从“只能本机跑”更接近“可以给可信任的人访问一个网址试用”。

## 7. 剩余问题

- 访问口令保存在浏览器 `localStorage`，不适合高安全场景。
- 共享口令泄露后无法追踪具体使用者。
- 没有请求限流和成本控制。
- 没有 HTTPS 时，口令可能在网络中暴露；正式公网部署必须使用 HTTPS。
- 面向更多用户时仍需要正式 Auth 模块。

## 8. 测试方法

- `scripts/check-local.ps1`
- `python -m compileall app`
- `npm exec tsc -- --noEmit`
- 手动验证：
  - `APP_ACCESS_PASSWORD` 为空时，本地功能保持可用。
  - `APP_ACCESS_PASSWORD` 非空且未输入口令时，`/api/v1/*` 返回 401。
  - 输入正确口令后，聊天、文件上传和 RAG API 可正常调用。
  - `GET /health` 不需要口令。
