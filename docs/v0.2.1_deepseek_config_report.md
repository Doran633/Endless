## 2. 修改文件说明

### 2.1 `backend/app/core/config.py`

修改原因：

- 原先只读取系统环境变量，不会自动读取本地 `.env`。

修改内容：

- 使用 `python-dotenv` 加载 `backend/.env`。
- 保持系统环境变量优先级高于 `.env`。
- 保持统一 `settings` 入口。

影响：

- 开发者可以通过 `backend/.env` 配置本地 API Key。
- Provider 仍然只通过 `settings` 获取配置，不硬编码 Key。

### 2.2 `backend/requirements.txt`

修改原因：

- 后端需要读取 `.env` 文件。

修改内容：

- 新增 `python-dotenv`。

影响：

- 新环境需要执行 `pip install -r requirements.txt`。

### 2.3 `backend/.env.example`

修改原因：

- 需要给开发者提供安全配置模板。

修改内容：

- 新增示例字段：
  - `LLM_PROVIDER`
  - `LLM_MODEL`
  - `LLM_TIMEOUT_SECONDS`
  - `OPENAI_API_KEY`
  - `OPENAI_BASE_URL`

影响：

- 别人拿到项目后可以复制此文件创建自己的 `backend/.env`。
- 示例文件不包含真实 API Key，可以提交到 Git。

### 2.4 `backend/app/main.py`

修改原因：

- 本地 Vite 开发服务器曾自动切换到 `5174`。

修改内容：

- CORS 允许 `http://localhost:5174` 和 `http://127.0.0.1:5174`。

影响：

- 当前开发联调可以同时支持 Vite 的 `5173` 和 `5174`。
- 不涉及业务功能扩展。

## 3. `.env` 安全机制

当前安全机制：

- `backend/.env` 存放真实敏感配置。
- `backend/.env.example` 存放示例配置。
- `.gitignore` 已忽略 `.env`。
- `git check-ignore -v backend/.env` 已确认命中：

```text
.gitignore:12:.env "backend\\.env"
```

因此：

- 真实 API Key 不会被 Git 跟踪。
- 前端不会接触 API Key。
- Provider 不硬编码 API Key。
- 后端统一通过 `settings.openai_api_key` 读取 Key。

注意：

- 不要把真实 Key 写入 `backend/.env.example`。
- 不要把真实 Key 写入文档。
- 不要把真实 Key 写入前端代码。
- 不要截图或公开展示 `backend/.env` 中的真实 Key。

## 4. DeepSeek 配置方式

本项目将 DeepSeek 当作 OpenAI-compatible Provider 使用。

`backend/.env` 示例：

```env
APP_NAME=WorkBuddy Backend

LLM_PROVIDER=openai
LLM_MODEL=deepseek-v4-flash
LLM_TIMEOUT_SECONDS=60

OPENAI_API_KEY=你的DeepSeek API Key
OPENAI_BASE_URL=https://api.deepseek.com
```

说明：

- `LLM_PROVIDER=openai` 表示使用 OpenAI-compatible 调用方式。
- `LLM_MODEL=deepseek-v4-flash` 表示实际调用 DeepSeek 模型。
- `OPENAI_API_KEY` 填 DeepSeek 控制台生成的 Key。
- `OPENAI_BASE_URL` 填 DeepSeek 的 OpenAI-compatible API 地址。
- 长文本生成建议将 `LLM_TIMEOUT_SECONDS` 设置为 `60`。

启动后端：

```text
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

如果响应中的 `model` 是 `deepseek-v4-flash`，说明真实外部模型已接通。

## 5. 别人如何使用自己的 API Key

别人拿到项目后，不会拿到你的真实 API Key。

他们需要：

1. 复制示例文件：

```text
backend/.env.example -> backend/.env
```

2. 填写自己的配置：

```env
LLM_PROVIDER=openai
LLM_MODEL=deepseek-v4-flash
LLM_TIMEOUT_SECONDS=60
OPENAI_API_KEY=他们自己的 API Key
OPENAI_BASE_URL=https://api.deepseek.com
```

3. 安装依赖：

```text
cd backend
pip install -r requirements.txt
```

4. 启动后端：

```text
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

如果他们没有 API Key，可以使用：

```env
LLM_PROVIDER=mock
```

这样项目仍然可以本地开发和前后端联调。

## 7. 当前剩余问题

### 7.1 后端进程管理

之前出现过多个 `uvicorn --reload` 旧进程占用 `8000`。

建议：

- 改 `.env` 后先停止旧后端进程。
- 使用 `netstat -ano | findstr :8000` 检查端口。
- 必要时使用 `Stop-Process -Id <PID> -Force`。

### 7.2 缺少自动化测试

当前主要依靠手动验证。

建议后续补：

- `GET /health`。
- `POST /api/v1/chat` mock 成功。
- `openai` 缺 Key 返回 `43001`。
- 未知 provider 返回配置错误。

### 7.3 长文本没有流式输出

当前前端等待完整回答后一次性展示。

影响：

- 1500 字长文生成时，用户会感觉页面等待较久。

后续建议：

- v1.0 后期再考虑 streaming。
- 当前不为了长文本提前引入 SSE/WebSocket。
