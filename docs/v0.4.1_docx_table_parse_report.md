# v0.4.1 DOCX 表格解析增强报告

> 本报告记录 v0.4.1 的 DOCX 表格解析改进。
> 本阶段不引入 RAG、Embedding、向量数据库、数据库、复杂任务队列或前端界面重构。

## 1. 本次完成内容

v0.4.1 聚焦一个问题：v0.4 虽然可以解析 DOCX 表格单元格文本，但会丢失行列关系，也不能稳定处理单元格里的嵌套表格。

本次增强后：

- DOCX 段落仍按原逻辑提取。
- DOCX 表格会按行输出。
- 同一行的单元格用 `|` 分隔。
- 表格单元格内的多个段落会合并为可读文本。
- 表格单元格内的嵌套表格会递归提取。
- 合并单元格导致的重复底层 cell 会尽量去重。

输出示例：

```text
投放方案
表格行1: 渠道 | 预算 | 转化率
表格行2: 抖音 | 10000 | 3.2%
表格行3: 小红书 | 8000 | 2.7%; 表格行1: 细分 | 数值; 表格行2: 女性 | 60%
```

## 2. 修改文件说明

`backend/app/services/document_parser_service.py`

- 改进 `_parse_docx()`。
- 从“段落 + 表格单元格平铺”改为“按文档块顺序解析段落和表格”。
- 新增内部 `iter_blocks()`，识别段落和表格块。
- 新增内部 `parse_container()`，递归解析文档主体或表格单元格。
- 新增内部 `parse_cell()`，处理单元格内段落和嵌套表格。
- 新增内部 `format_table()`，按行输出表格文本。

`docs/status.md`

- 更新当前版本为 `v0.4.1`。
- 补充 DOCX 表格解析增强状态。

## 3. 设计原因

企业文档、投放方案、合同和分析报告经常把关键数据放在表格里。

如果表格解析只是把所有单元格打散，会影响后续能力：

- 文本预览可读性差。
- 临时文档问答难以理解表格关系。
- 后续 chunk 会缺少“同一行数据属于同一组信息”的上下文。
- 未来 RAG 检索命中后，LLM 看到的上下文质量会降低。

因此 v0.4.1 不做复杂版式还原，只做 MVP 需要的文本结构增强：

```text
保留表格行
保留单元格分隔
支持嵌套表格
保持纯文本输出
```

结果：通过。

## 5. 当前仍不解决的问题

v0.4.1 仍不做：

- Word 文本框解析。
- 图片 OCR。
- 扫描件 PDF OCR。
- 复杂合并单元格版式还原。
- 表格样式识别。
- 表格转 Excel。
- 表格坐标定位。
- RAG 问答。
- Embedding。
- 数据库持久化。

## 6. 后续影响

对后续 RAG 的正面影响：

- chunk 时可以按表格行保留更完整的信息单元。
- LLM 更容易理解同一行中的字段关系。
- 表格型业务文档的回答质量会更稳定。

潜在技术债：

- 当前仍是纯文本表达，不是真正结构化表格对象。
- 嵌套表格会被压成同一行中的文本，复杂文档可能仍不够漂亮。
- 后续如要做严肃数据分析，应新增专门的表格抽取结构，而不是复用文档解析文本。
