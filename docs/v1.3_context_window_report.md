# v1.3.1 Backend Basic Context Window 报告

## 1. 工程效果

v1.3.1 为普通聊天增加了最小上下文窗口。

完成后：

- `POST /api/v1/chat` 携带 `session_id` 时，后端会读取当前会话最近 6 条历史消息。
- 最近历史消息会转换为 LLM messages。
- 当前用户消息会追加到最后。
- LLM 可以在普通聊天中理解当前会话内的连续追问。
- 无 `session_id` 时，普通聊天仍保持旧的单轮行为。
- RAG 文件问答主链路不变。

本阶段不实现长期记忆、不实现历史消息语义检索、不实现会话摘要、不实现 RAG 多轮追问。

## 2. 修改文件职责

### `backend/app/repositories/chat_repository.py`

新增 `list_recent_messages(session_id, limit)`。

职责：

- 按 `session_id` 查询最近 N 条消息。
- 数据库层按 `created_at desc` 取最近消息。
- 返回前反转为正序，方便直接传给 LLM。
- 不拼 prompt，不处理 token，不判断业务规则。

### `backend/app/services/chat_service.py`

新增 `answer_with_context(messages)`。

职责：

- 接收已经组装好的 LLM messages。
- 自动在最前面注入北辰agent system prompt。
- 调用现有 `LLMService.chat()`。
- 返回原有 `answer/model/usage` 结构。

原 `answer(content)` 保留，并复用 `answer_with_context()`，所以无 `session_id` 的旧聊天仍可工作。

### `backend/app/services/conversation_service.py`

`answer_and_persist_chat()` 改为：

- 读取当前会话最近 6 条历史消息。
- 过滤 `user` / `assistant` 消息。
- 每条历史消息最多保留 1200 个字符。
- 将历史消息转换为 `ChatMessage`。
- 追加当前用户消息。
- 调用 `ChatService.answer_with_context()`。
- 保持原有 user / assistant 消息保存逻辑。
- 保持自动标题逻辑。

### `docs/status.md`

同步当前阶段到 v1.3.1。

## 3. 普通聊天上下文调用链

```text
Frontend
-> POST /api/v1/chat { message, session_id }
-> API Router
-> ConversationService.answer_and_persist_chat()
-> ChatRepository.list_recent_messages(session_id, 6)
-> ConversationService 转换历史消息并截断
-> 追加当前 user message
-> ChatService.answer_with_context(messages)
-> LLMService
-> LLMProvider
-> ChatRepository.create_message(user)
-> ChatRepository.create_message(assistant)
-> maybe_update_session_title()
-> 返回原 ChatResponse
```

## 4. 为什么不影响 RAG

本阶段只修改普通聊天持久化路径：

```text
POST /api/v1/chat
```

没有修改：

- `RagService`
- `RetrievalService`
- `VectorStoreService`
- `POST /api/v1/files/{file_id}/ask` 的 RAG 检索和 prompt 组装逻辑

因此 RAG 文件问答仍按原来的流程工作：

```text
query + file_id
-> RetrievalService
-> RAG prompt
-> LLMProvider
```

## 5. token 风险和当前截断策略

风险：

- 历史消息越多，prompt 越长。
- 如果历史里包含长代码、长报告或长 RAG 回答，会增加模型成本和响应时间。
- 超过模型上下文限制时可能导致调用失败。

当前策略：

- 只取最近 6 条历史消息。
- 每条历史消息最多保留 1200 个字符。
- 超出后追加 `...`。
- 当前用户消息仍保留现有请求长度限制。

本阶段不做 tokenizer-aware 截断，也不做精确 token 预算。

## 6. 这仍不是长期记忆

v1.3.1 实现的是“短期上下文窗口”。

它能让模型理解当前会话最近几轮对话，但它不是长期记忆：

- 不跨会话。
- 不保存用户偏好。
- 不做历史语义检索。
- 不做会话摘要。
- 不从长期历史中主动召回信息。

长期记忆需要后续单独设计 embedding、检索、摘要、权限和遗忘策略。

## 7. 测试结果

已运行：

```powershell
python -m compileall app
```

结果：通过。

已运行：

```powershell
npm exec tsc -- --noEmit
```

结果：通过。

已使用 API / 测试替身验证：

- 创建会话。
- 第一轮普通聊天写入消息。
- 第二轮普通聊天携带 `session_id` 时，`ChatService` 收到最近历史 + 当前消息。
- 最近历史最多取 6 条。
- 长历史消息会按 1200 字符截断。
- 无 `session_id` 的普通聊天仍是单轮。
- RAG API 不带普通聊天上下文，行为保持不变。

## 8. 当前剩余问题

- RAG 多轮追问尚未实现。
- 会话摘要尚未实现。
- 历史消息语义检索尚未实现。
- 上下文窗口没有精确 token 预算。
- 前端暂未显示“已使用上下文”的提示。
