# v1.2.4 Frontend Conversation Recovery 报告

## 1. 工程效果

v1.2.4 将前端聊天状态接入 v1.2 后端会话 API，让会话和消息从前端临时状态升级为可恢复状态。

完成后：

- 前端启动时加载后端会话列表。
- 如果没有会话，自动创建默认“新对话”。
- 前端维护 `currentSessionId`。
- 切换会话时从后端加载历史消息。
- 普通聊天发送时携带当前 `session_id`。
- 聊天侧 RAG 问答发送时携带当前 `session_id`。
- 聊天侧文件完成 indexed 后，绑定到当前会话。
- 刷新后根据 `session.bound_file_id` 恢复当前 RAG 文件提示。
- 删除会话时调用后端 API，并同步前端本地缓存。

本阶段没有修改后端 RAG 主链路，没有实现历史消息作为 LLM 上下文，也没有实现长期记忆或多文件 RAG。

## 2. 修改文件职责

### `frontend/src/api/chatApi.ts`

新增会话 API client：

- `listChatSessions()`
- `createChatSession()`
- `deleteChatSession()`
- `listChatMessages()`
- `bindChatSessionFile()`

同时 `sendChatMessage()` 增加可选 `sessionId`，用于让后端写入普通聊天消息。

### `frontend/src/api/fileApi.ts`

`askFile()` 增加可选 `sessionId`。

当聊天侧执行 RAG 问答时，前端会把当前会话 ID 传给后端，让后端保存 RAG user/assistant 消息。

### `frontend/src/types/index.ts`

新增：

- `ChatSession`
- `ChatMessage`
- `ChatMessageMetadata`

并扩展前端 `Session` 和 `Message` 类型，以兼容后端会话、消息和 RAG metadata。

### `frontend/src/stores/chatStore.ts`

重构为以后端会话和消息为真实来源：

- `loadSessions()`：加载后端会话；无会话时自动创建默认会话。
- `selectSession()`：切换会话并拉取历史消息。
- `createSession()`：调用后端创建会话。
- `deleteSession()`：调用后端删除会话。
- `bindRagFileToCurrentSession()`：调用后端绑定当前会话文件。
- `clearCurrentSessionRagFile()`：调用后端解除文件绑定。
- `sendMessage()`：发送普通聊天或 RAG 问答时携带当前 `session_id`。

### `frontend/src/components/ChatLayout.tsx`

应用进入工作台时先加载文件列表，再加载会话列表。

这样刷新后可以用 `bound_file_id` 在文件列表中恢复当前 RAG 文件名称。

### `frontend/src/components/Sidebar.tsx`

新建、切换和删除会话改为异步调用后端 API。

### `frontend/src/components/ChatInput.tsx`

文件完成自动处理并 indexed 后，绑定到当前会话。

清除当前文件时，也同步解除后端会话绑定。

### `frontend/src/components/FileCenter.tsx`

删除当前绑定文件时，等待聊天会话解除绑定。

文件中心本身的检索和问答能力保持原样。

### `frontend/src/components/WelcomePage.tsx`

快捷开始改为先异步创建后端会话，再发送消息。

### `docs/status.md`

同步当前版本到 v1.2.4。

## 3. 前端会话恢复调用链

```text
ChatLayout mount
-> fileStore.loadFiles()
-> chatStore.loadSessions()
-> GET /api/v1/chat/sessions
-> 如果 sessions 为空：POST /api/v1/chat/sessions
-> 设置 currentSessionId
-> GET /api/v1/chat/sessions/{session_id}/messages
-> 渲染历史消息
-> 根据 bound_file_id 从 fileStore.files 中恢复 RAG 文件提示
```

## 4. 普通聊天持久化前端调用链

```text
ChatInput.handleSend()
-> chatStore.sendMessage(content)
-> POST /api/v1/chat { message, session_id }
-> 后端 ConversationService 保存 user / assistant
-> 前端追加临时消息
-> 重新拉取当前会话消息
-> 历史消息以后端记录为准
```

## 5. RAG 问答持久化前端调用链

```text
ChatInput.handleSend()
-> chatStore.sendMessage(content)
-> 当前会话存在 sessionRagFiles[currentSessionId]
-> POST /api/v1/files/{file_id}/ask { query, top_k, session_id }
-> 后端 RagService 生成回答
-> 后端 ConversationService 保存 user / assistant + metadata_json
-> 前端展示回答和参考片段
-> 重新拉取当前会话消息
```

## 6. 刷新后如何恢复 bound_file_id

刷新后：

```text
fileStore.loadFiles()
-> chatStore.loadSessions()
-> 后端 session 包含 bound_file_id
-> chatStore 将 bound_file_id 映射为 session.fileId
-> 从 fileStore.files 查找文件名
-> 写入 sessionRagFiles[sessionId]
-> ChatInput 展示当前绑定文件
```

如果文件已经被删除，后端删除流程会清除对应会话的 `bound_file_id`，刷新后前端不会恢复一个失效文件。

## 7. 仍未实现 LLM 上下文记忆

本阶段实现的是前端恢复历史消息，不是让模型自动读取历史。

当前行为：

- 用户能看到刷新前的历史消息。
- 新消息会继续保存到数据库。
- RAG 引用片段可以从 metadata 恢复展示。

尚未实现：

- 新请求自动携带最近 N 轮历史消息。
- 长对话摘要。
- 历史消息语义检索。
- 长期记忆。

后续如果要提升连续对话智能程度，应在持久会话稳定后单独设计上下文窗口策略。

## 9. 当前剩余问题

- 会话标题仍不会根据首条消息自动改名。
- 前端仍使用乐观消息追加，再拉取后端消息替换，极端慢网络下可能有短暂重复感。
- 当前只支持单会话绑定单文件。
- LLM 仍不会自动读取历史消息作为上下文。
- SQLite 表结构仍未引入 migration 系统。
