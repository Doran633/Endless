# v0.8 Retrieval 检索服务报告

## 1. 本次完成内容

v0.8 完成了最小 Retrieval 本地检索闭环。

当前链路：

```text
file_id + query
  -> MockEmbeddingProvider 生成 query embedding
  -> VectorStoreService.load_file_vectors(file_id)
  -> RetrievalService 计算 cosine similarity
  -> 返回 top_k chunks
```

前端文件中心可以对 `indexed` 文件执行检索测试，并展示：

- query
- score
- chunk_index
- chunk 内容

本阶段没有实现 RAG、文件问答、LLM 调用、真实 embedding API、PostgreSQL / pgvector 或多文件全局检索。

## 3. 当前调用链路

后端链路：

```text
POST /api/v1/files/{file_id}/retrieve
  -> RetrieveFileRequest(query, top_k)
  -> RetrievalService.retrieve()
  -> EmbeddingService.provider.embed_texts([query])
  -> VectorStoreService.load_file_vectors(file_id)
  -> _cosine_similarity(query_vector, item.embedding)
  -> score 降序排序
  -> RetrieveFileResponse
```

前端链路：

```text
FileCenter
  -> 点击 indexed 文件的“检索”
  -> 输入 query 和 top_k
  -> retrieveFileChunks()
  -> POST /api/v1/files/{file_id}/retrieve
  -> 展示 top_k chunks 和 score
```

## 4. 工程效果

v0.8 之后，项目已经具备 RAG 的检索前置能力：

```text
已索引文件
  -> 用户 query
  -> 找出相关 chunks
```

这一步验证的是：

- 本地 VectorStore 能被读取。
- query 能被转换为 mock vector。
- chunk vectors 能被遍历和打分。
- top_k 结果能返回给前端。

它仍不是文件问答。

## 5. 相似度算法

当前使用 cosine similarity：

```text
score = dot(a, b) / (norm(a) * norm(b))
```

排序规则：

```text
score 降序
chunk_index 升序作为稳定次级排序
```

边界处理：

- 向量维度不一致时抛出 `RetrievalError`。
- 空向量时抛出 `RetrievalError`。
- norm 为 0 时返回 `0.0`。

## 6. 当前能力边界

当前可以：

- 对单个 indexed 文件执行检索。
- 返回 top_k chunks。
- 展示 score 和 chunk 内容。

当前不能：

- 调用 LLM 生成答案。
- 自动在聊天区引用文件。
- 多文件全局检索。
- 使用真实 embedding API。
- 使用 pgvector。
- 评估真实语义检索质量。

## 8. 剩余问题

当前技术债：

- mock embedding 不代表真实语义。
- JSON 遍历检索只适合 MVP 和小文件。
- chunk 策略仍是字符数切块。
- 还没有文件元数据持久化。
- 还没有多文件检索。
- 还没有 RagService。
