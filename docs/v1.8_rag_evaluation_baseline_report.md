# v1.8.2 RAG Evaluation Baseline 实现报告

## 1. 本阶段目标

v1.8.2 不新增 AI 业务功能，不修改数据库结构，不引入 pgvector，不引入复杂 rerank，也不做多文件 RAG。

本阶段目标是建立人工 RAG 测评基线，让后续 RAG 优化不再依赖主观感觉，而是可以通过固定测试集、debug_trace 指标和人工评分进行对比。

## 5. 测评表如何使用

推荐流程：

1. 选择一份固定测试文档。
2. 上传并完成解析、切块、embedding 和索引。
3. 基于文档设计 10-20 个测试问题。
4. 将问题填入 `docs/rag_test_cases_template.csv`。
5. 在文件中心或聊天侧逐个提问。
6. 记录实际回答和 debug_trace 指标。
7. 根据评分规则人工打分。
8. 计算汇总指标。
9. 修改一个 RAG 参数。
10. 重新索引同一份文档，再跑同一批问题。
11. 比较指标变化。

## 6. 每个指标怎么计算

### Hit Rate@K

```text
retrieval_score >= 1 的问题数 / 总问题数
```

表示正确依据是否进入 top_k。

### Top-1 Accuracy

```text
retrieval_score = 2 的问题数 / 总问题数
```

表示正确依据是否排在第 1。

### Groundedness Rate

```text
groundedness_score >= 1 的问题数 / 总问题数
```

表示回答是否至少大体有文档依据。

### High-quality Answer Rate

```text
groundedness_score = 2 的问题数 / 总问题数
```

表示回答是否完全有文档依据。

### Citation Precision

```text
citation_score >= 1 的问题数 / 总问题数
```

表示引用片段是否至少相关。

### No-answer Accuracy

只统计 `has_answer = no` 的问题：

```text
no_answer_score = 1 的问题数 / no_answer 问题总数
```

表示文档没有答案时是否正确拒答。

### Token Usage

记录：

```text
平均 input_tokens
平均 output_tokens
```

用于观察成本和上下文长度压力。

## 7. 配置化参数如何调整

后端 `.env`：

```env
CHUNK_SIZE=800
CHUNK_OVERLAP=120
RAG_DEFAULT_TOP_K=3
```

调整后需要：

1. 重启后端。
2. 删除旧索引或重新上传同一份测试文档。
3. 等待重新解析、切块、embedding 和索引完成。
4. 使用同一批问题重新测试。

不要只改参数后直接问旧索引，因为旧索引仍然来自旧切块参数。

## 8. 如何比较不同参数组合

推荐一次只改一个变量：

```text
基线：chunk_size=800, chunk_overlap=120, top_k=3
方案 A：chunk_size=1000, chunk_overlap=120, top_k=3
方案 B：chunk_size=800, chunk_overlap=160, top_k=3
方案 C：chunk_size=800, chunk_overlap=120, top_k=5
```

比较：

- Hit Rate@K 是否提升。
- Top-1 Accuracy 是否提升。
- Groundedness 是否提升。
- No-answer Accuracy 是否下降。
- Citation Precision 是否提升。
- input_tokens 是否明显增加。
- 响应速度是否明显变慢。

如果准确率提升很小，但 token 和延迟明显增加，不建议采用该参数。

## 9. 为什么暂不自动评分

当前测试集尚未稳定，自动评分容易带来假精确。

例如：

- LLM-as-judge 会引入额外成本和不稳定性。
- 字符串匹配无法判断语义正确。
- 引用是否支撑答案仍需要人工判断。

当前阶段先用人工评分建立基线。等测试集稳定后，再考虑自动化批量评测。

## 10. 当前限制

- 配置化参数需要重启后端生效。
- 改变 chunk 参数后必须重新生成索引。
- 前端聊天侧 `VITE_RAG_DEFAULT_TOP_K` 需要重新 build 才会生效。
- 当前仍不做 score threshold。
- 当前仍不做自动评测。
- 当前仍不持久化完整 trace。
