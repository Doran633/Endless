# v1.5.2 Production Build & VPS Deployment Guide Plan

## 1. 当前部署准备状态

当前项目已经具备从本地 MVP 走向小范围线上试运行的基础：

- 前端：React + Vite，可以通过 `npm run build` 生成静态文件。
- 后端：FastAPI，可以通过 Uvicorn / Gunicorn 运行。
- 数据：SQLite 保存文件元数据、会话和消息。
- 文件：`backend/uploads/` 保存上传原始文件。
- 索引：`backend/vector_store/` 保存本地 JSON chunks 和 embeddings。
- AI：LLM Provider 与 Embedding Provider 已支持 OpenAI-compatible API。
- 安全：v1.5.1 已加入 `APP_ACCESS_PASSWORD` 最小访问口令保护。
- 文档：已有 README、本地试运行指南、故障排查文档和 GitHub Safety Check。

当前还没有完成正式部署所需的生产运行说明：

- 没有服务器目录结构约定。
- 没有前端生产构建和发布路径说明。
- 没有后端常驻进程方案。
- 没有 Nginx 配置示例。
- 没有 HTTPS 配置流程。
- 没有线上数据备份、回滚和日志排查流程。

## 2. 为什么现在先做部署指南

v1.5.2 不继续新增 AI 功能，原因是当前项目已经有完整 RAG MVP 闭环，但从“本机能跑”到“别人打开网址能试用”还差工程化部署步骤。

如果跳过部署指南直接上服务器，容易出现：

- API Key 暴露或被滥用。
- SQLite、uploads、vector_store 放错目录，更新代码时被覆盖。
- 前端生产包仍然调用本地开发地址。
- Nginx 路径转发错误导致 `Failed to fetch`。
- HTTPS 缺失导致浏览器安全限制和口令传输风险。
- 没有备份，服务器重装或误操作后数据丢失。

所以 v1.5.2 的目标是先把部署路线写成可执行手册，再进入实际配置文件和脚本整理。

## 3. 推荐服务器配置

适合当前 MVP 的低成本 VPS：

- CPU：1 到 2 核。
- 内存：1 GB 起步，推荐 2 GB。
- 磁盘：20 GB 起步，推荐 40 GB。
- 系统：Ubuntu 22.04 LTS 或 Ubuntu 24.04 LTS。
- 带宽：1 Mbps 到 5 Mbps 均可用于小范围试用。
- 域名：一个普通域名即可，例如 `beichen.example.com`。

推荐先选择小型付费云服务器，而不是免费平台。

原因：

- 当前项目依赖 SQLite、本地上传文件和本地 JSON vector_store。
- 免费平台常见问题是休眠、磁盘不持久、文件会丢、后端冷启动慢。
- VPS 虽然需要自己维护，但最贴合当前项目的单机 MVP 形态。

## 4. 推荐服务器目录结构

建议把代码、运行数据、日志和备份分开：

```text
/opt/beichen-agent/
  app/                  # Git 拉取的项目代码
  venv/                 # Python 虚拟环境
  frontend_dist/        # 前端 npm run build 后的 dist
  runtime/
    backend.env         # 生产环境变量，不提交 Git
    data/               # SQLite 数据库
    uploads/            # 上传原始文件
    vector_store/       # 本地 JSON 索引
  logs/
    backend.log
    backend.err.log
  backups/
    data/
    uploads/
    vector_store/
```

这样做的好处：

- 更新代码时不会覆盖运行数据。
- `.env` 不放在 Git 目录中，降低误提交风险。
- Nginx 只暴露前端静态目录，不暴露后端数据目录。
- 备份路径清晰。

## 5. 前端 build 流程

本地或服务器上构建前端：

```powershell
cd frontend
npm install
npm run build
```

生产部署时，推荐让前端调用同域名下的 `/api/v1/*`，这样可以避免复杂 CORS。

推荐方式：

- 前端 `VITE_API_BASE_URL` 留空。
- 浏览器访问 `https://your-domain.com`。
- 前端请求 `/api/v1/chat`。
- Nginx 把 `/api/` 转发给 FastAPI。

构建产物：

```text
frontend/dist/
```

部署时复制到：

```text
/opt/beichen-agent/frontend_dist/
```

## 6. 后端运行流程

服务器上建议使用 Python 虚拟环境：

```bash
cd /opt/beichen-agent/app/backend
python3 -m venv /opt/beichen-agent/venv
source /opt/beichen-agent/venv/bin/activate
pip install -r requirements.txt
```

后端生产启动建议先使用 Uvicorn 单进程：

```bash
source /opt/beichen-agent/venv/bin/activate
cd /opt/beichen-agent/app/backend
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

后续可以用 systemd 托管，让它开机自启、异常重启，并把日志写入文件。

当前不建议过早引入 Gunicorn 多 worker，原因是：

- SQLite 不适合复杂并发写入。
- 本地文件和 JSON vector_store 是单机状态。
- 当前 MVP 更需要稳定和可理解，而不是高并发。

## 7. Nginx 配置方案

Nginx 负责两件事：

- 返回前端静态文件。
- 把 `/api/` 和 `/health` 转发到 FastAPI。

示例配置：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /opt/beichen-agent/frontend_dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 25m;
    }

    location /health {
        proxy_pass http://127.0.0.1:8000/health;
        proxy_set_header Host $host;
    }
}
```

注意：

- `client_max_body_size` 要大于后端 `MAX_UPLOAD_SIZE_MB`。
- 不要把 `backend/uploads/`、`backend/vector_store/`、`backend/data/` 配成静态目录。
- 前端刷新路由时必须用 `try_files $uri $uri/ /index.html`。

## 8. HTTPS 配置方案

建议使用 Certbot 为 Nginx 自动配置 HTTPS：

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

HTTPS 的意义：

- 保护访问口令传输。
- 保护聊天内容和上传文件传输。
- 避免浏览器对不安全请求的限制。
- 为后续正式登录、Cookie 或更多安全策略做准备。

上线后应强制 HTTP 跳转 HTTPS。

## 9. 环境变量配置方案

生产环境变量建议放在：

```text
/opt/beichen-agent/runtime/backend.env
```

示例：

```env
APP_NAME=Beichen Agent Backend
APP_ACCESS_PASSWORD=请填写真实访问口令
APP_ACCESS_HEADER=X-Beichen-Access

LLM_PROVIDER=openai
LLM_MODEL=deepseek-v4-flash
LLM_TIMEOUT_SECONDS=60
OPENAI_API_KEY=请填写真实 API Key
OPENAI_BASE_URL=https://api.deepseek.com

EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSION=1536
EMBEDDING_TIMEOUT_SECONDS=60
EMBEDDING_API_KEY=请填写真实 Embedding API Key
EMBEDDING_BASE_URL=https://api.openai.com/v1

DATABASE_PATH=/opt/beichen-agent/runtime/data/beichen.db
UPLOAD_DIR=/opt/beichen-agent/runtime/uploads
VECTOR_STORE_DIR=/opt/beichen-agent/runtime/vector_store
MAX_UPLOAD_SIZE_MB=20
ALLOWED_UPLOAD_EXTENSIONS=txt,pdf,docx
```

注意：

- 不要把真实 `backend.env` 提交到 GitHub。
- 不要把真实 API Key 写进 README 或 docs。
- 如果使用 DeepSeek 聊天模型和 OpenAI embedding，需要分别配置两个 provider。

## 10. SQLite / uploads / vector_store 持久化方案

当前线上 MVP 继续保留本地持久化：

- SQLite：保存文件元数据、会话、消息、绑定文件状态。
- uploads：保存原始上传文件。
- vector_store：保存 chunks、embedding vectors 和可检索文本。

风险：

- vector_store JSON 中包含文档 chunk 原文，不只是向量。
- SQLite 和本地文件都依赖服务器磁盘。
- 单机部署不能横向扩容。
- 多用户并发写入能力有限。

备份建议：

```text
/opt/beichen-agent/backups/
  data/
  uploads/
  vector_store/
```

最小备份策略：

- 每天备份 SQLite。
- 每天备份 uploads 和 vector_store。
- 更新版本前先做一次手动备份。
- 备份文件不要公开下载。

## 11. 日志方案

后端日志建议写入：

```text
/opt/beichen-agent/logs/backend.log
/opt/beichen-agent/logs/backend.err.log
```

Nginx 日志默认在：

```text
/var/log/nginx/access.log
/var/log/nginx/error.log
```

排查顺序：

1. 浏览器控制台看前端请求是否 401、404、502。
2. Nginx error log 看反向代理是否失败。
3. 后端日志看 FastAPI 是否报错。
4. 检查 `backend.env` 是否加载正确。
5. 检查 `uploads`、`vector_store`、`data` 目录权限。

## 12. 更新部署流程

推荐更新流程：

1. 在本地完成开发并提交 Git。
2. 推送到 GitHub。
3. SSH 登录服务器。
4. 备份 SQLite、uploads、vector_store。
5. 在服务器拉取最新代码。
6. 安装新增后端依赖。
7. 安装新增前端依赖。
8. 重新构建前端。
9. 复制 `dist` 到 `frontend_dist`。
10. 重启后端服务。
11. 重载 Nginx。
12. 访问网页做手动验收。

示例：

```bash
cd /opt/beichen-agent/app
git pull
cd backend
source /opt/beichen-agent/venv/bin/activate
pip install -r requirements.txt
cd ../frontend
npm install
npm run build
rm -rf /opt/beichen-agent/frontend_dist/*
cp -r dist/* /opt/beichen-agent/frontend_dist/
sudo systemctl restart beichen-agent
sudo nginx -t
sudo systemctl reload nginx
```

## 13. 回滚方案

最小回滚策略：

1. 记录每次部署前的 Git commit。
2. 部署前备份 runtime 数据。
3. 如果新版本异常，回退代码到上一个 commit。
4. 重新 build 前端。
5. 重启后端。
6. 必要时恢复 SQLite、uploads、vector_store 备份。

示例：

```bash
cd /opt/beichen-agent/app
git log --oneline -5
git checkout 上一个稳定提交号
```

注意：

- 当前项目没有 migration 系统，回滚前后如果未来涉及数据库结构变化，需要额外小心。
- v1.5.2 阶段不改数据库结构，所以回滚风险较低。

## 14. 安全注意事项

必须做到：

- 服务器 `.env` 或 `backend.env` 不进入 Git。
- 真实 API Key 不写进任何文档。
- `backend/uploads/` 不暴露为静态目录。
- `backend/vector_store/` 不暴露为静态目录。
- `backend/data/` 不暴露为静态目录。
- 必须开启 HTTPS。
- 必须设置 `APP_ACCESS_PASSWORD`。
- 访问口令应足够长，不要使用简单密码。

当前仍未解决：

- 没有正式用户登录。
- 没有请求限流。
- 没有用户隔离。
- 没有文件配额。
- 没有后台管理。
- 没有操作审计。

因此，v1.5 部署仍适合个人项目、小范围可信任试用，不适合公开发布给大量未知用户。
