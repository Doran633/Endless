# v1.5.5 Local Debug Health Report

## 1. 工程效果

本阶段新增 `GET /health/config`，用于查看当前运行后端实际读取到的非敏感配置。它解决的是本地调试中“我以为配置改了，但浏览器可能仍连着旧后端”的判断问题。

本阶段没有新增 AI 业务功能，没有修改 RAG 主链路，也没有修改数据库结构。

## 2. 修改文件职责

- `backend/app/api/v1/health.py`：新增 `/health/config` 路由，并组装非敏感配置摘要。
- `backend/app/schemas/health.py`：新增健康配置响应 schema，让返回结构稳定。
- `docs/status.md`：同步当前阶段状态。
- `docs/v1.5_debug_health_report.md`：记录本阶段实现内容、边界和测试方式。

## 3. /health/config 返回字段

接口返回：

- `app_name`
- `llm_provider`
- `llm_model`
- `embedding_provider`
- `embedding_model`
- `embedding_dimension`
- `database_path`
- `upload_dir`
- `vector_store_dir`
- `access_control.enabled`
- `access_control.mode`
- `access_control.header`
- `access_control.invite_code_count`

`access_control.mode` 可能是：

- `disabled`
- `invite_codes`
- `legacy_password`

## 4. 为什么不返回敏感信息

该接口用于调试当前进程配置，不是管理后台。因此只返回“配置形态”，不返回“配置秘密”。

它不会返回：

- `OPENAI_API_KEY`
- `EMBEDDING_API_KEY`
- `APP_ACCESS_PASSWORD`
- `APP_INVITE_CODES` 原文
- 上传文件内容
- 文件列表
- 聊天记录
- chunks
- embeddings

邀请码只返回数量，不返回具体值。

## 5. 如何帮助定位旧进程和旧配置问题

如果你访问：

```text
http://127.0.0.1:8000/health/config
```

看到：

```text
embedding_model = mock-embedding
embedding_dimension = 16
```

但你本地 `.env` 明明已经改成 `BAAI/bge-m3 / 1024`，就说明当前 8000 上响应请求的是旧后端或旧配置进程。

如果你再启动 8001 并访问：

```text
http://127.0.0.1:8001/health/config
```

看到：

```text
embedding_model = BAAI/bge-m3
embedding_dimension = 1024
```

就能直接判断：前端应该连接 8001，或者需要清理 8000 旧后端。

## 6. 它不能直接解决端口占用

`/health/config` 只能观察配置，不能控制进程。

它不能：

- 杀掉旧后端。
- 释放 8000 端口。
- 判断 Windows 上哪个 PID 应该被结束。
- 解决 `uvicorn --reload` 父子进程问题。

它的价值是减少误判，让你快速知道问题在“旧进程/旧配置”，而不是 RAG、embedding API 或 `.env` 内容。

## 7. 测试方法

基础验证：

- `scripts/check-local.ps1`
- `python -m compileall app`
- `npm exec tsc -- --noEmit`

接口验证：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health/config
```

重点确认：

- `embedding_model`
- `embedding_dimension`
- `access_control.mode`
- `access_control.invite_code_count`

安全检查：

- 响应中不包含真实 API Key。
- 响应中不包含真实邀请码。
- 响应中不包含上传文件内容。
