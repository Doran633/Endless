北辰agent 小范围上线试运行计划

一、项目背景

北辰agent 是一个独立网页版 AI 助手 MVP，当前面向 1 到 5 名可信试用者开放。项目的核心目标不是替代完整企业系统，而是验证 AI 聊天、文件上传、文档解析、单文件 RAG 问答、会话持久化、匿名用户隔离和基础部署运维能力是否可以形成稳定闭环。

当前系统已经完成公网 IP 试运行验证，后端部署在 Ubuntu VPS 上，使用 Nginx 代理前端静态资源和 FastAPI 后端服务。系统使用邀请码作为最小访问保护方式，使用匿名 client_id 隔离不同浏览器用户的文件、会话和消息。

二、当前已完成功能

1. 普通 AI 聊天

用户可以在聊天窗口中输入问题，系统会调用 OpenAI-compatible LLM Provider 返回回答。普通聊天支持当前会话最近 6 条消息作为短上下文，因此用户可以进行基础连续追问。

2. 文件上传与自动处理

用户可以上传 TXT、DOCX、文本型 PDF 文件。上传后系统会自动执行文档解析、文本切块、embedding 生成和本地 JSON VectorStore 索引保存。文件处理完成后，该文件可以用于单文件 RAG 问答。

3. 单文件 RAG 问答

当前系统支持基于一个已索引文件进行问答。用户提问后，系统会对问题生成 query embedding，再从该文件的本地向量索引中检索相关 chunks，将检索结果和问题一起交给 LLM 生成回答。

4. 会话和消息持久化

系统使用 SQLite 保存聊天会话、聊天消息、文件元数据和文件处理状态。刷新页面后，用户可以恢复历史会话、历史消息和当前会话绑定文件。

5. 匿名用户隔离

前端首次访问时会生成匿名 client_id，并保存在浏览器 localStorage 中。所有业务 API 请求都会携带 X-Beichen-Client-Id。后端会按照 client_id 隔离文件、会话和消息。

三、试运行范围

本次试运行只面向可信试用者，不进行公开传播。

试运行人数上限为 5 人。

单个上传文件大小上限为 20MB。

推荐测试文件类型为 TXT、DOCX 和文本型 PDF。

暂不支持扫描件 PDF 的 OCR 识别。

暂不支持多文件 RAG。

暂不支持正式账号密码登录。

暂不支持微信登录或手机号登录。

六、RAG 质量观察指标

本次试运行关注以下 RAG 质量指标：

1. Retrieval Hit Rate

测试问题对应的正确依据是否出现在 top_k 检索片段中。

2. Top-1 Accuracy

正确依据是否排在第一个检索片段。

3. Groundedness

AI 回答是否基于文档内容，而不是使用模型常识编造。

4. Citation Precision

展示的引用片段是否真的支撑回答。

5. No-answer Accuracy

当文档中没有答案时，系统是否能回答“根据当前文档内容无法确认”。

6. Token Usage

记录 input tokens 和 output tokens，观察成本和上下文长度压力。

七、已知限制和风险

1. 当前是单文件 RAG，不支持跨多个文件综合问答。

2. 当前使用 SQLite 和本地 JSON VectorStore，适合小范围试用，不适合高并发公开使用。

3. 邀请码不是正式登录系统，不能提供账号、角色、权限审计或跨设备同步。

4. 文本型 PDF 可以解析，扫描件 PDF 无法解析。

5. RAG 检索质量受 chunk_size、chunk_overlap、embedding 模型和 top_k 影响。

6. 如果检索片段相关度较低，系统可能出现答非所问或依据不足的问题。

7. 上传文件、vector_store 和 SQLite 数据库都属于运行时私有数据，不能提交到 GitHub，也不应随意分享。

八、下一步优化方向

第一，建立 RAG 人工测评基线，使用固定测试文档和固定问题记录 debug_trace、检索分数、引用片段和人工评分。

第二，配置化并测试 chunk_size、chunk_overlap 和 top_k，比较不同参数下的 Hit Rate、Groundedness 和 Token Usage。

第三，在掌握分数分布后，增加 RAG_SCORE_THRESHOLD 和无答案处理，减少低相关问题下的幻觉回答。

第四，在单文件 RAG 稳定后，再考虑多文件 RAG Lite。

第五，在用户规模扩大到 20 到 50 人前，规划账号密码登录、邀请码注册、用户数据隔离和基础限流。

九、测试注意事项

测试者应使用同一份测试文档和同一组问题进行多轮对比。每次调整 RAG 参数后，必须重新生成文件索引，不能直接使用旧索引比较新参数效果。

测试结果应该记录问题、实际回答、命中片段、最高相关度、平均相关度、置信度、无答案判断、input tokens、output tokens 和人工评分。

如果答案看起来流畅但引用片段无法支撑结论，应判定为低质量回答。

如果文档中没有答案而系统明确回答无法确认，应判定为良好的拒答行为。
