# v1.7.3 Backend Baseline Tests 报告

## 1. 本阶段工程效果

本阶段完成 v1.7.3 Backend Baseline Tests。

本次没有新增 AI 业务功能，没有修改 RAG 主链路，没有修改数据库结构。目标是建立最小后端自动化测试框架，用来保护当前公网小范围试用最容易回归的后端边界。

新增测试覆盖：

- `/health`
- `/health/config`
- 邀请码访问保护
- `X-Beichen-Client-Id` 基础校验
- 文件列表按 `client_id` 隔离
- 文件删除不能跨 `client_id`
- 会话列表按 `client_id` 隔离
- 会话消息读取和删除不能跨 `client_id`

## 2. 新增文件职责

### `backend/requirements-dev.txt`

职责：

- 管理开发和测试依赖。
- 通过 `-r requirements.txt` 复用生产运行依赖。
- 增加 `pytest` 和 `httpx`。

设计原因：

- 测试依赖不直接混入生产最小依赖。
- VPS 生产部署仍可只安装 `requirements.txt`。

### `backend/tests/conftest.py`

职责：

- 在导入 FastAPI app 之前设置测试环境变量。
- 创建临时 SQLite、uploads、vector_store 和 logs 目录。
- 强制测试使用 Mock LLM 和 Mock Embedding。
- 提供 FastAPI `TestClient`。
- 提供默认测试请求头：
  - `X-Beichen-Access`
  - `X-Beichen-Client-Id`

设计原因：

- 当前项目 settings 和数据库 engine 在模块导入时初始化，因此必须先设置测试环境，再导入 `app.main`。
- 这样可以避免测试读取或污染真实 `backend/data`、`backend/uploads` 和 `backend/vector_store`。

### `backend/tests/test_health.py`

职责：

- 测试 `/health`。
- 测试 `/health/config`。
- 确认配置健康接口只返回非敏感摘要。

覆盖风险：

- 健康检查被误改。
- `/health/config` 暴露 API Key、邀请码原文或敏感配置。

### `backend/tests/test_access_control.py`

职责：

- 测试缺少邀请码时业务 API 被拒绝。
- 测试错误邀请码被拒绝。
- 测试正确邀请码可以访问业务 API。
- 测试 `/health` 不需要邀请码。

覆盖风险：

- 公网部署时 `/api/v1/*` 被无保护访问。
- 健康检查被错误加入访问保护，影响部署探活。

### `backend/tests/test_client_context.py`

职责：

- 测试缺少 `X-Beichen-Client-Id` 时返回稳定错误。
- 测试超长 `client_id` 被拒绝。

覆盖风险：

- 匿名隔离边界被绕过。
- 非法 client_id 进入后端数据层。

### `backend/tests/test_file_isolation.py`

职责：

- 测试 client A 上传文件后只有 client A 可见。
- 测试 client B 不能删除 client A 的文件。

覆盖风险：

- 文件列表跨用户泄露。
- 文件删除跨 client_id 误删。

### `backend/tests/test_session_isolation.py`

职责：

- 测试 client A 创建会话后只有 client A 可见。
- 测试 client B 不能读取 client A 的消息。
- 测试 client B 不能删除 client A 的会话。

覆盖风险：

- 会话列表跨用户泄露。
- 历史消息跨 client_id 读取。
- 会话删除跨 client_id 误删。

## 3. 测试数据隔离方式

测试使用 Python 临时目录：

```text
beichen-agent-tests-*
```

测试环境变量会指向临时路径：

- `DATABASE_PATH`
- `DATABASE_URL`
- `UPLOAD_DIR`
- `VECTOR_STORE_DIR`
- `LOG_DIR`

测试默认配置：

```text
LLM_PROVIDER=mock
EMBEDDING_PROVIDER=mock
APP_INVITE_CODES=111111
APP_ACCESS_HEADER=X-Beichen-Access
```

因此测试不会：

- 调用真实 LLM。
- 调用真实 embedding。
- 读取真实 SQLite。
- 污染真实 uploads。
- 污染真实 vector_store。
- 打印真实 API Key 或真实邀请码。

## 4. 自动化测试的原理

本阶段的自动化测试不是通过浏览器点击页面完成的，而是在后端代码层完成。

核心原理：

1. pytest 负责发现并运行 `backend/tests/test_*.py`。
2. FastAPI `TestClient` 在测试进程里加载后端 app。
3. 测试代码直接向 app 发起 HTTP 请求，例如 `GET /health`、`GET /api/v1/files`。
4. 后端会像真实运行一样经过 middleware、router、service、repository。
5. 测试断言响应状态码、响应 body、隔离规则和错误码是否符合预期。

这意味着：

- 不需要真的打开浏览器。
- 不需要真的启动 Uvicorn 端口。
- 不需要真的连接公网。
- 不需要真实 LLM / embedding API。

但它仍然能验证后端业务规则有没有被破坏。

## 5. 覆盖了哪些风险

当前测试已经覆盖：

- 健康接口可用性。
- 非敏感配置接口安全边界。
- 邀请码保护是否生效。
- 缺失 client_id 是否被拒绝。
- 文件列表是否按 client_id 隔离。
- 文件删除是否按 client_id 校验。
- 会话列表是否按 client_id 隔离。
- 会话消息读取是否按 client_id 校验。
- 会话删除是否按 client_id 校验。

## 6. 暂缓的测试

本阶段暂缓：

- 真实 LLM 调用测试。
- 真实 embedding 调用测试。
- RAG 端到端问答测试。
- DOCX / PDF 复杂解析测试。
- Nginx 反向代理测试。
- systemd 服务测试。
- 浏览器自动化测试。
- 性能和并发测试。

原因：

- v1.7.3 的目标是建立基础测试骨架。
- 外部模型测试会增加费用、网络依赖和不稳定性。
- RAG 端到端测试链路更长，适合后续独立补充。

## 7. 如何运行

安装测试依赖：

```powershell
cd backend
pip install -r requirements-dev.txt
```

运行全部后端测试：

```powershell
pytest
```

运行单个测试文件：

```powershell
pytest tests/test_health.py
```

建议部署前本地验证顺序：

```powershell
cd backend
python -m compileall app
pytest
cd ../frontend
npm exec tsc -- --noEmit
```

## 8. 当前方案限制

当前测试仍是基础测试。

限制：

- 没有覆盖完整 RAG 主链路。
- 没有覆盖真实外部 Provider。
- 没有覆盖前端。
- 没有覆盖服务器 Nginx 和 systemd。
- 没有覆盖备份和恢复脚本在真实 Ubuntu 上的执行结果。

但它已经能保护当前最重要的后端安全边界和数据隔离规则。
