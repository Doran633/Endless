# v1.2.5 Auto Session Title 自动会话标题报告

## 1. 工程效果

v1.2.5 解决了所有会话都显示“新对话”、难以辨别的问题。

完成后：

- 普通聊天成功持久化后，如果当前会话标题仍是默认“新对话”，会自动使用用户问题生成标题。
- RAG 问答成功持久化后，如果当前会话标题仍是默认“新对话”，会自动使用用户问题生成标题。
- 前端发送消息后会重新拉取 sessions，因此左侧会话标题会更新。
- 刷新页面后标题仍保存在 SQLite 中。
- 普通聊天系统提示已统一为“北辰agent”，不再残留 WorkBuddy 身份。
- 前端发送消息时会先进行一次本地标题乐观更新，后端 sessions API 仍是最终真实来源。

本阶段没有新增 API，没有修改数据库结构，没有调用额外 LLM，也没有改变 RAG 主链路。

## 2. 自动标题规则

标题生成规则：

- 使用用户第一条消息或 RAG query。
- 去除换行和多余空格。
- 内容为空时不更新标题。
- 最长 24 个字符。
- 超出 24 个字符后追加 `...`。
- 只有标题仍为默认“新对话”时才更新，避免覆盖用户后续可能编辑的标题。

示例：

```text
输入：请帮我总结这份合同里的主要风险，并按照严重程度排序
标题：请帮我总结这份合同里的主要风险，并按照严...
```

## 3. 修改文件职责

### `backend/app/repositories/chat_repository.py`

新增 `update_session_title()`：

- 按 `session_id` 查询会话。
- 更新 `title`。
- 同步刷新 `updated_at`。
- 提交数据库事务。

Repository 仍只负责数据库读写，不判断是否应该自动生成标题。

### `backend/app/services/conversation_service.py`

新增：

- `maybe_update_session_title()`
- `_build_auto_title()`

普通聊天和 RAG 问答成功保存消息后，调用 `maybe_update_session_title()`。

`ConversationService` 负责判断：

- 会话是否存在。
- 当前标题是否仍为默认“新对话”。
- 用户输入是否能生成有效标题。

### `backend/app/services/chat_service.py`

修正普通聊天 system prompt：

- AI 身份统一为“北辰agent”。
- 不再自称 WorkBuddy。
- 不声明日程、企业权限、企业系统等当前未实现能力。

### `frontend/src/stores/chatStore.ts`

新增前端标题乐观更新：

- 用户发送消息后，如果当前会话标题仍为“新对话”，立即用同样的标题规则更新侧边栏展示。
- 后端仍会在消息持久化成功后更新 SQLite。
- 前端随后重新拉取 sessions，用后端结果覆盖本地状态。

## 4. 普通聊天标题更新调用链

```text
POST /api/v1/chat { message, session_id }
-> ConversationService.answer_and_persist_chat()
-> ChatService.answer()
-> ChatRepository.create_message(user)
-> ChatRepository.create_message(assistant)
-> ConversationService.maybe_update_session_title(message)
-> ChatRepository.update_session_title()
-> 前端重新拉取 sessions
-> 左侧标题更新
```

## 5. RAG 问答标题更新调用链

```text
POST /api/v1/files/{file_id}/ask { query, top_k, session_id }
-> ConversationService.ask_file_and_persist()
-> RagService.ask_file()
-> ChatRepository.create_message(user)
-> ChatRepository.create_message(assistant + metadata_json)
-> ConversationService.maybe_update_session_title(query)
-> ChatRepository.update_session_title()
-> 前端重新拉取 sessions
-> 左侧标题更新
```

## 6. 为什么不调用 LLM 起标题

本阶段不调用 LLM，是为了保持 MVP 简单稳定：

- 不增加一次额外模型调用成本。
- 不增加响应延迟。
- 不增加标题生成失败点。
- 不引入标题 prompt 管理。

当前标题只需要解决“新对话太多无法区分”的产品问题，用本地规则已经足够。

后续如果需要更自然的标题，可以在会话持久化稳定后再增加可选的 LLM 标题生成。

## 8. 当前剩余问题

- 仍不支持用户手动重命名会话。
- 仍不调用 LLM 生成更自然标题。
- 自动标题只在默认标题时触发，不会覆盖已存在标题。
- LLM 仍不会自动读取历史消息作为上下文。
