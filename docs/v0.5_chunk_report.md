# v0.5 文本切块报告

> 本报告记录 v0.5 文本切块闭环的实现结果。
> 本阶段不包含 LLM 文件问答、Embedding、向量数据库、RAG、数据库持久化或复杂任务队列。

## 1. 工程效果

v0.5 完成后，北辰agent 的文件处理链路从“能解析文档”推进到“能把解析文本切成 chunks”。

当前链路：

```text
文件上传
  -> FileService 保存原文件
  -> DocumentParserService 提取全文
  -> ChunkService 切分文本
  -> 返回 chunk_count 和 chunk_preview
  -> 前端展示 chunk 数量和预览
```

用户侧效果：

- 上传 TXT / DOCX / PDF。
- 点击“解析”。
- 解析完成后点击“切块”。
- 文件状态变为“已切块”。
- 文件列表展示 chunk 数量。
- 点击 “chunks” 可以查看前几个 chunk 的内容预览。

这一步仍不是 RAG。

当前只是为后续 Embedding 和检索准备文本单元。

## 2. 改动思路

### 2.1 保持服务分层

本次没有把切块逻辑放进 `DocumentParserService`。

原因：

- `DocumentParserService` 负责“从文件抽文本”。
- `ChunkService` 负责“把文本切成检索单元”。
- 后续 `EmbeddingService` 会接 `ChunkService` 的输出。

分层关系：

```text
FileService
  -> 保存文件

DocumentParserService
  -> 提取文本

ChunkService
  -> 切分文本

EmbeddingService
  -> 生成向量
```

这样可以避免文档解析服务越来越重，也更符合真实 RAG 工程结构。

### 2.2 为什么重新解析全文

当前项目还没有数据库，也没有解析全文持久化。

因此 `POST /api/v1/files/{file_id}/chunks` 会：

```text
根据 file_id + extension 重新读取文件
  -> DocumentParserService.parse_text()
  -> ChunkService.chunk_text()
```

这是 v0.5 的 MVP 方案。

后续引入数据库后，应改成：

```text
file_id
  -> 查询 document_text
  -> chunk_text
  -> 保存 chunks
```

### 2.3 为什么只返回 chunk preview

本阶段只返回前 3 个 chunk。

原因：

- 大文档可能生成大量 chunk。
- 前端只是验证切块结果，不需要承担 chunk 全量存储。
- 后续 embedding 阶段，chunk 全量应进入数据库或向量存储。

## 3. 新增内容作用

### 3.1 `backend/app/services/chunk_service.py`

新增 `ChunkService`。

作用：

- 负责文本规范化。
- 按固定字符数切块。
- 生成 chunk index。
- 生成 chunk id。
- 返回 chunk 数量和 chunk 预览。

当前策略：

```text
chunk_size = 800
chunk_overlap = 120
preview_limit = 3
```

### 3.2 `backend/app/api/v1/files.py`

新增接口：

```text
POST /api/v1/files/{file_id}/chunks
```

作用：

- 接收前端切块请求。
- 使用 `DocumentParserService` 提取全文。
- 使用 `ChunkService` 切块。
- 返回统一 JSON 响应。

### 3.3 `backend/app/schemas/file.py`

新增 Schema：

- `ChunkFileRequest`
- `DocumentChunk`
- `ChunkFileResponse`

作用：

- 明确切块请求和响应字段。
- 为后续 embedding 和向量存储提供稳定数据形状。

### 3.4 `backend/app/core/errors.py`

新增 `ChunkError`。

作用：

- 空文本或切块失败时返回稳定错误。

### 3.5 `backend/app/services/document_parser_service.py`

新增 `parse_text()`。

作用：

- 复用已有 TXT / DOCX / PDF 解析逻辑。
- 给 `ChunkService` 提供解析全文。
- 避免在切块接口中重复实现文件解析。

### 3.6 `frontend/src/api/fileApi.ts`

新增 `chunkFile(fileId, extension)`。

作用：

- 调用后端切块接口。
- 将错误转换为前端可展示消息。

### 3.7 `frontend/src/stores/fileStore.ts`

新增 `chunkFile(id)`。

作用：

- 管理切块中的状态。
- 切块成功后将文件状态更新为 `chunked`。
- 保存 `chunk_count`、`chunk_preview` 和 `chunked_at`。

### 3.8 `frontend/src/types/index.ts`

新增 `DocumentChunk`。

扩展 `FileItem`：

- `status` 增加 `chunked`。
- 新增 `chunk_count`。
- 新增 `chunk_preview`。
- 新增 `chunked_at`。

### 3.9 `frontend/src/components/FileCenter.tsx`

新增：

- “切块”按钮。
- “chunks” 预览按钮。
- `chunked` 状态展示。
- chunk 数量展示。
- chunk 预览弹窗。

## 4. 当前调用链路

```text
FileCenter.handleChunk(file)
  -> fileStore.chunkFile(file.id)
  -> fileApi.chunkFile(file.id, file.extension)
  -> POST /api/v1/files/{file_id}/chunks
  -> DocumentParserService.parse_text(file_id, extension)
  -> ChunkService.chunk_text(file_id, text)
  -> ChunkFileResponse
  -> 前端状态更新为 chunked
  -> 用户查看 chunk 预览
```

## 5. 测试结果

已运行：

```text
python -m compileall app
```

结果：通过。

已运行：

```text
npm exec tsc -- --noEmit
```

结果：通过。

已验证 `ChunkService`：

- 长文本可以切成多个 chunk。
- 每个 chunk 有 `chunk_id`、`chunk_index`、`content`、`char_count`。
- 前 3 个 chunk 会作为 preview 返回。

已验证 API：

- 上传长 TXT 成功。
- 解析长 TXT 成功。
- 调用 `POST /api/v1/files/{file_id}/chunks` 成功。
- 返回 `status=chunked`。
- 返回 `chunk_count=5`。
- 返回 `chunk_preview`。

已验证异常：

- 不存在的 `file_id` 调用切块接口，返回 HTTP 404。
- 复用 `DocumentNotFoundError`，错误码 `44001`。

## 6. 当前限制

- chunk 结果不持久化。
- 页面刷新后 chunk 状态丢失。
- 切块接口仍需要前端传 `extension`。
- 当前是字符数切块，不是 token-aware chunk。
- 当前可能切断句子或表格行。
- 当前不做 embedding。
- 当前不做向量存储。
- 当前不做 RAG 问答。
