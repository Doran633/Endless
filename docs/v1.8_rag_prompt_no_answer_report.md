# v1.8.7 RAG Prompt Strictness and No-answer Policy 报告

## 1. 本次工程效果

v1.8.7 在现有单文件 RAG 闭环上增加了更严格的回答边界：

- RagService 在调用 LLM 前先根据检索结果判断 `answer_policy`。
- 当检索为空或相关度过低时，后端直接返回“根据当前文档内容无法确认。”，不再调用 LLM。
- 当检索结果偏弱但未达到拒答阈值时，RAG prompt 会明确提示模型低置信，要求它不能硬编。
- debug trace 增加 `answer_policy` 和 `no_answer_reason`，便于人工测评 No-answer Accuracy。
- 前端文件中心和聊天侧 RAG 引用区域可以看到回答策略摘要。

这一步不改变 Retrieval、VectorStore、Embedding 主链路，只是在 RAG 生成前增加轻量策略判断和更严格 prompt。

## 3. 新版 RAG Prompt 规则

RAG prompt 当前明确要求：

1. 只能根据提供的 document chunks 回答。
2. 不能使用外部常识或自行猜测补全答案。
3. 如果 chunks 不能支撑答案，必须回答“根据当前文档内容无法确认”。
4. 如果能回答，尽量标注依据来自哪些 Chunk。
5. 如果 answer policy 是 `low_confidence_answer`，额外提醒模型当前检索置信度偏低。

这比之前更适合文档问答场景，因为它把“能不能回答”作为模型必须遵守的边界，而不是只让模型自由生成。

## 4. answer_policy 判断逻辑

当前策略是规则判断，不调用额外模型：

- `retrieved_count = 0`
  - `answer_policy = no_answer`
  - `no_answer_reason = empty_retrieval`

- `max_score < 0.45`
  - `answer_policy = no_answer`
  - `no_answer_reason = low_score`

- 所有 used chunks 的 `relevance_level` 都是 `weak`
  - `answer_policy = low_confidence_answer`
  - `no_answer_reason = weak_chunks`

- `0.45 <= max_score < 0.55`
  - `answer_policy = low_confidence_answer`
  - `no_answer_reason = low_score`

- 其他情况
  - `answer_policy = grounded_answer`
  - `no_answer_reason = null`

如果模型在回答中主动表达无法确认，最终策略会记录为：

- `answer_policy = no_answer`
- `no_answer_reason = model_refusal`

## 5. no_answer_reason 含义

- `empty_retrieval`
  - 没有检索到任何可用片段。

- `low_score`
  - 检索最高分低于当前阈值，说明问题和文档片段整体相关性不足。

- `weak_chunks`
  - 有片段被检索到，但所有片段都被标记为弱相关。

- `model_refusal`
  - 后端允许模型回答，但模型根据 prompt 判断资料不足并拒答。

## 6. 为什么不调用 LLM 做评分

本阶段不引入 LLM 评分，是为了保持 MVP 简单和成本可控：

- 不增加额外 API 调用成本。
- 不增加调用延迟。
- 不引入“评分模型自己也可能误判”的新不确定性。
- 当前人工测评阶段更需要透明规则，而不是黑盒判断。

等固定测评集稳定后，再考虑 rerank 或 LLM-as-judge 会更合理。

## 7. 如何评估 No-answer Accuracy

建议在 `docs/rag_test_cases_template.csv` 中加入一组“文档中没有答案”的问题，例如：

- “这个项目支持微信登录吗？”
- “系统是否已经接入 pgvector？”
- “当前是否支持扫描件 PDF OCR？”
- “是否支持 100 人同时使用？”

每个问题记录：

- `no_answer`
- `answer_policy`
- `no_answer_reason`
- `actual_answer`
- `groundedness_score`
- `citation_score`
- `no_answer_score`

评分建议：

- 文档确实没有答案，系统回答无法确认：`no_answer_score = 1`
- 文档确实没有答案，但系统编造：`no_answer_score = 0`
- 文档中有答案，但系统误拒答：`no_answer_score = 0`

## 8. 当前限制

- 阈值 `0.45` 和 `0.55` 是 MVP 经验值，需要继续通过测试集校准。
- `model_refusal` 只通过中文关键词粗略识别，不是完整自然语言分类。
- `low_confidence_answer` 仍可能回答正确，也可能混入噪声，需要人工观察。
- 本阶段仍没有 rerank、pgvector、多文件 RAG 或自动评分。
