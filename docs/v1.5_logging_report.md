# v1.5.7 Local Error Logging 实现报告

## 1. 本次完成内容

本阶段新增了最小后端日志能力：每个请求都会带有 `request_id`，响应 header 返回 `X-Request-Id`，`AppError` 错误响应 body 也会返回同一个 `request_id`。后端会记录请求开始、请求完成、请求异常和应用错误摘要。

日志默认输出到后端控制台；如果在 `backend/.env` 中配置 `LOG_TO_FILE=true`，则会写入 `backend/logs/app.log`。

## 2. 修改文件职责

- `backend/app/core/logging_config.py`：集中配置 Python logging，支持控制台输出和可选本地文件输出。
- `backend/app/core/request_context.py`：生成和读取 `request_id`，统一使用 `X-Request-Id` 作为关联 header。
- `backend/app/main.py`：注册请求日志 middleware，记录请求生命周期并给响应写入 `X-Request-Id`。
- `backend/app/core/exception_handlers.py`：在 `AppError` 响应中加入 `request_id`，并记录应用错误摘要。
- `backend/app/core/config.py`：新增 `LOG_LEVEL`、`LOG_TO_FILE`、`LOG_DIR` 配置读取。
- `backend/.env.example`：新增日志配置示例。
- `.gitignore`：明确忽略 `backend/logs/` 和日志文件。
- `docs/status.md`：同步 v1.5.7 当前状态。

## 3. request_id 调用链

```text
Frontend / API Client
-> FastAPI request_logging_middleware
-> 生成或读取 X-Request-Id
-> request.state.request_id
-> API Router / Service / Provider
-> 成功响应：header 返回 X-Request-Id
-> AppError：exception_handler 从 request.state 读取 request_id
-> 错误响应 body 和 header 都返回 request_id
```

## 4. 日志记录内容

当前日志记录：

- `request_start`：`request_id`、HTTP method、path。
- `request_complete`：`request_id`、HTTP method、path、status_code、duration_ms。
- `request_exception`：未处理异常摘要和堆栈。
- `app_error`：应用错误类型、业务错误码、HTTP 状态码、path、摘要 message。

这些日志可以覆盖 LLM、Embedding、文件处理、RAG 等模块抛出的 `AppError`，帮助定位是哪一类后端能力失败。

## 5. 不记录的敏感内容

当前日志不会主动记录：

- API Key。
- 真实邀请码。
- 访问口令。
- 完整用户消息。
- 完整 prompt。
- 上传文件内容。
- chunks 原文。
- embeddings 向量。

因此日志适合用于本地和小型部署排查，但仍不应公开分享日志文件。

## 6. 如何根据 request_id 排查错误

当前端或 API 调用失败时：

1. 查看响应 header 中的 `X-Request-Id`。
2. 如果是 `AppError`，查看响应 body 中的 `request_id`。
3. 在后端控制台或 `backend/logs/app.log` 中搜索该 request_id。
4. 根据同一个 request_id 找到请求开始、完成或异常记录。

## 7. 本地从哪里查看日志

默认方式：

- 查看运行 `python -m uvicorn app.main:app ...` 的 PowerShell 窗口。

文件方式：

- 在 `backend/.env` 设置 `LOG_TO_FILE=true`。
- 日志文件位置为 `backend/logs/app.log`。

## 8. 部署后从哪里查看日志

如果使用 systemd：

- 优先查看 `journalctl -u beichen-agent -f`。

如果开启文件日志：

- 查看服务器项目目录下的 `backend/logs/app.log`。
