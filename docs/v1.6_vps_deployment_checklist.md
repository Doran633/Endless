# v1.6.0 VPS Deployment Checklist

## 1. 当前结论

当前项目已经可以进入小型 VPS 部署准备阶段，但仍建议先按本清单核对模板、配置、域名、HTTPS、备份和验收步骤。

推荐部署路线：

```text
Ubuntu VPS
-> Nginx
   -> frontend_dist 静态文件
   -> 127.0.0.1:8000 FastAPI
-> systemd 守护后端
-> SQLite + uploads + vector_store + logs 保存在服务器本地 runtime 目录
```

本阶段不引入 Docker，不新增 AI 功能，不修改 RAG 主链路，不修改数据库结构。

## 2. 部署模板核对

### 2.1 Nginx 模板

文件：`deploy/nginx/beichen-agent.conf.example`

当前状态：可用于 Ubuntu VPS 单机部署。

它负责：

- 监听 `80`。
- 使用 `server_name example.com www.example.com` 占位。
- 从 `/opt/beichen-agent/frontend_dist` 托管 React/Vite 静态文件。
- 将 `/api/` 反向代理到 `127.0.0.1:8000/api/`。
- 将 `/health` 和 `/health/config` 反向代理到 FastAPI。
- 设置 `client_max_body_size 25m`，匹配当前 MVP 文件上传规模。

上线前必须替换：

- `example.com`
- `www.example.com`

### 2.2 systemd 模板

文件：`deploy/systemd/beichen-agent.service.example`

当前状态：可用于守护 FastAPI 后端。

它负责：

- 使用 `www-data` 运行后端。
- 工作目录：`/opt/beichen-agent/app/backend`。
- 环境变量文件：`/opt/beichen-agent/runtime/backend.env`。
- Python 虚拟环境：`/opt/beichen-agent/venv`。
- 后端监听：`127.0.0.1:8000`。
- systemd 失败自动重启。
- 将 stdout/stderr 写入 `/opt/beichen-agent/logs/`。

上线前必须确认：

- 服务器实际路径是否仍使用 `/opt/beichen-agent`。
- `www-data` 是否有 runtime、logs 和 app 目录访问权限。
- `backend.env` 是否存在且不提交 Git。

## 4. 服务器购买建议

### 4.1 推荐配置

个人 MVP 推荐：

```text
系统：Ubuntu 22.04 LTS 或 24.04 LTS
CPU：2 核优先，1 核可试用
内存：2GB 推荐，1GB 勉强可用
硬盘：40GB 推荐，20GB 勉强可用
带宽：2Mbps 以上，越高越好
```

为什么推荐 2GB：

- Node build 会吃内存。
- Python 后端、Nginx、SQLite、文件解析会同时占用资源。
- 1GB 服务器可能需要 swap，否则 `npm run build` 容易失败。

### 4.2 地域选择

如果主要用户在中国大陆：

- 大陆服务器访问速度好，但绑定域名通常需要备案。
- 香港服务器通常无需备案，但网络稳定性取决于服务商和线路。

如果只是可信任小范围试用：

- 可以先用香港 VPS + 域名。
- 也可以先不用域名，用公网 IP 试运行，但不建议长期使用 HTTP 明文。

## 5. 域名购买和 DNS 解析

购买域名后添加 DNS：

```text
类型：A
主机记录：@
记录值：你的服务器公网 IP

类型：A
主机记录：www
记录值：你的服务器公网 IP
```

如果想使用子域名：

```text
类型：A
主机记录：agent
记录值：你的服务器公网 IP
```

对应访问：

```text
https://agent.example.com
```

DNS 生效后再配置 Nginx 和 Certbot。

## 6. Ubuntu VPS 初始化

登录服务器：

```bash
ssh root@your_server_ip
```

安装基础包：

```bash
sudo apt update
sudo apt install -y git nginx python3 python3-venv python3-pip nodejs npm certbot python3-certbot-nginx
```

检查版本：

```bash
python3 --version
node --version
npm --version
nginx -v
```

## 7. 服务器目录结构

创建目录：

```bash
sudo mkdir -p /opt/beichen-agent/app
sudo mkdir -p /opt/beichen-agent/frontend_dist
sudo mkdir -p /opt/beichen-agent/runtime/data
sudo mkdir -p /opt/beichen-agent/runtime/uploads
sudo mkdir -p /opt/beichen-agent/runtime/vector_store
sudo mkdir -p /opt/beichen-agent/logs
sudo mkdir -p /opt/beichen-agent/backups
sudo chown -R www-data:www-data /opt/beichen-agent
```

目录职责：

- `/opt/beichen-agent/app`：GitHub 项目源码。
- `/opt/beichen-agent/frontend_dist`：前端生产构建文件。
- `/opt/beichen-agent/runtime/data`：SQLite 数据库。
- `/opt/beichen-agent/runtime/uploads`：上传原始文件。
- `/opt/beichen-agent/runtime/vector_store`：本地 JSON 向量索引，包含 chunk 文本。
- `/opt/beichen-agent/logs`：后端和 systemd 日志。
- `/opt/beichen-agent/backups`：部署前备份。

cd /opt/beichen-agent/app

## 9. 生产 backend.env 配置

创建：

```bash
sudo nano /opt/beichen-agent/runtime/backend.env
sudo chown www-data:www-data /opt/beichen-agent/runtime/backend.env
sudo chmod 600 /opt/beichen-agent/runtime/backend.env
```

示例结构：

```env
APP_NAME=Beichen Agent Backend
APP_ACCESS_HEADER=X-Beichen-Access
APP_INVITE_CODES=123456,654321
APP_ACCESS_PASSWORD=

LLM_PROVIDER=openai
LLM_MODEL=deepseek-v4-flash
LLM_TIMEOUT_SECONDS=60
OPENAI_API_KEY=replace-with-real-key
OPENAI_BASE_URL=https://api.deepseek.com

EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=BAAI/bge-m3
EMBEDDING_DIMENSION=1024
EMBEDDING_TIMEOUT_SECONDS=60
EMBEDDING_API_KEY=replace-with-real-key
EMBEDDING_BASE_URL=https://api.siliconflow.cn/v1

DATABASE_PATH=/opt/beichen-agent/runtime/data/beichen.db
UPLOAD_DIR=/opt/beichen-agent/runtime/uploads
VECTOR_STORE_DIR=/opt/beichen-agent/runtime/vector_store
MAX_UPLOAD_SIZE_MB=20
ALLOWED_UPLOAD_EXTENSIONS=txt,pdf,docx

LOG_LEVEL=INFO
LOG_TO_FILE=true
LOG_DIR=/opt/beichen-agent/logs
```

注意：

- 不要把真实 API Key 写入 Git。
- 不要把真实邀请码写入 Git。
- `APP_INVITE_CODES` 是多个 6 位数字邀请码，用英文逗号分隔。
- `APP_INVITE_CODES` 非空时优先使用邀请码；为空时才回退到 `APP_ACCESS_PASSWORD`。

## 10. 后端 venv 和依赖安装

```bash
cd /opt/beichen-agent/app/backend
sudo -u www-data python3 -m venv /opt/beichen-agent/venv
sudo -u www-data /opt/beichen-agent/venv/bin/pip install -r requirements.txt
sudo -u www-data /opt/beichen-agent/venv/bin/python -m compileall app
```

手动测试：

```bash
sudo -u www-data /opt/beichen-agent/venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另开终端：

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/health/config
```

确认正常后停止手动 Uvicorn。

## 11. systemd 启动后端

```bash
sudo cp /opt/beichen-agent/app/deploy/systemd/beichen-agent.service.example /etc/systemd/system/beichen-agent.service
sudo systemctl daemon-reload
sudo systemctl enable beichen-agent
sudo systemctl start beichen-agent
sudo systemctl status beichen-agent
```

查看日志：

```bash
journalctl -u beichen-agent -f
tail -f /opt/beichen-agent/logs/backend.log
tail -f /opt/beichen-agent/logs/backend.err.log
tail -f /opt/beichen-agent/logs/app.log
```

## 12. 前端 build 和静态托管

```bash
cd /opt/beichen-agent/app/frontend
sudo -u www-data npm install
sudo -u www-data npm run build
sudo rm -rf /opt/beichen-agent/frontend_dist/*
sudo cp -r dist/* /opt/beichen-agent/frontend_dist/
sudo chown -R www-data:www-data /opt/beichen-agent/frontend_dist
```

生产模式下推荐前端使用同源请求，所以 `VITE_API_BASE_URL` 可以不配置。

## 13. Nginx 配置

```bash
sudo cp /opt/beichen-agent/app/deploy/nginx/beichen-agent.conf.example /etc/nginx/sites-available/beichen-agent
sudo nano /etc/nginx/sites-available/beichen-agent
```

必须替换：

```nginx
server_name your-domain.com www.your-domain.com;
root /opt/beichen-agent/frontend_dist;
```

启用：

```bash
sudo ln -s /etc/nginx/sites-available/beichen-agent /etc/nginx/sites-enabled/beichen-agent
sudo nginx -t
sudo systemctl reload nginx
```

Nginx 职责：

- `/`：返回前端静态文件。
- `/api/`：转发到 FastAPI。
- `/health` 和 `/health/config`：转发到 FastAPI。
- 不暴露 `runtime/data`、`runtime/uploads`、`runtime/vector_store`。

## 14. HTTPS / Certbot

DNS 生效后执行：

```bash
sudo certbot --nginx -d your-domain.com -d www.your-domain.com
```

检查自动续期：

```bash
sudo certbot renew --dry-run
```

公网试用必须使用 HTTPS，因为请求里包含邀请码、聊天内容和上传文件。

## 15. SQLite / uploads / vector_store / logs 持久化

必须持久化：

- `/opt/beichen-agent/runtime/data`
- `/opt/beichen-agent/runtime/uploads`
- `/opt/beichen-agent/runtime/vector_store`
- `/opt/beichen-agent/runtime/backend.env`

建议保留但可轮转：

- `/opt/beichen-agent/logs`

`vector_store` JSON 包含 chunk 文本，属于隐私数据，不应公开。

服务器本机：

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/health/config
```

公网：

```bash
curl https://your-domain.com/health

```

浏览器验证：

- 打开 `https://your-domain.com`。
- 输入邀请码。
- 发送普通聊天。
- 上传小 TXT 文件。
- 等待自动处理完成。
- 基于该文件提问。

```powershell

```

## 18. 常见失败排查

### 18.1 502 Bad Gateway

原因：

- 后端 systemd 没启动。
- Uvicorn 没监听 `127.0.0.1:8000`。
- Nginx proxy_pass 配错。

排查：

```bash
sudo systemctl status beichen-agent
journalctl -u beichen-agent -f
curl http://127.0.0.1:8000/health
```

### 18.2 前端刷新 404

原因：

- Nginx 缺少 SPA fallback。

检查：

```nginx
try_files $uri $uri/ /index.html;
```

### 18.3 上传失败或 413

原因：

- Nginx `client_max_body_size` 太小。
- 后端 `MAX_UPLOAD_SIZE_MB` 太小。
- uploads 目录权限不足。

### 18.4 401

原因：

- 邀请码未输入。
- 邀请码错误。
- 前端请求 header 与后端 `APP_ACCESS_HEADER` 不一致。

### 18.5 LLM / Embedding 失败

排查：

- `OPENAI_API_KEY`
- `OPENAI_BASE_URL`
- `EMBEDDING_API_KEY`
- `EMBEDDING_BASE_URL`
- 模型名称
- 后端日志中的 `request_id`

### 18.6 RAG 回答失败

排查：

- 文件是否 indexed。
- vector_store 路径是否正确。
- embedding 维度是否和索引一致。
- LLM 是否可调用。

## 20. 部署前还差什么

在真正购买服务器并上线前，还需要：

- 选择 VPS 服务商和地域。
- 购买或准备域名。
- 决定是否使用 `www` 域名。
- 生成生产邀请码。
- 准备生产 LLM API Key。
- 准备生产 Embedding API Key。
- 决定是否先用香港服务器跳过备案。
- 决定谁可以拿到邀请码试用。

## 21. 本地部署未来迁移到 Docker 的影响

先使用当前 VPS + Nginx + systemd 路线，未来改 Docker 不算麻烦，但需要做一次部署结构迁移。

需要迁移的部分：

- 后端启动方式：从 systemd 直接运行 Uvicorn，改为容器运行 Uvicorn。
- 前端构建方式：从服务器 `npm run build`，改为 Docker build 或独立静态镜像。
- Nginx：可以继续宿主机 Nginx，也可以迁入容器。
- 环境变量：从 `/opt/beichen-agent/runtime/backend.env`，改为 Docker env_file。
- 持久化目录：SQLite、uploads、vector_store、logs 需要挂载 Docker volume。

不会重写的部分：

- FastAPI 业务代码。
- React 前端代码。
- RAG 主链路。
- SQLite 表结构。
- uploads 和 vector_store 的数据格式。

所以当前路线不会把你锁死。它反而能帮助你先理解真实部署链路。等未来需要多人复制部署、CI/CD、Redis、PostgreSQL 或 worker 时，再引入 Docker 更合适。
