# v1.0.0 Real Embedding MVP 实现报告

## 1. 工程效果

v1.0.0 将 embedding 能力从 mock 工程验证升级为可配置的 OpenAI-compatible 真实 embedding 调用。

当前链路：

```text
聊天框上传文件
  -> 文件上传
  -> 文档解析
  -> 文本切块
  -> EmbeddingService
  -> MockEmbeddingProvider 或 OpenAIEmbeddingProvider
  -> 本地 JSON VectorStore
  -> RetrievalService
  -> RagService
  -> 聊天侧 RAG 回答
```

本阶段仍保持 MVP 范围：

- 不引入数据库。
- 不引入 pgvector。
- 不实现多文件 RAG。
- 不实现历史对话检索。
- 不实现 Agent。
- 不实现企业权限。
- 不修改 RAG 主链路结构。

## 2. 修改文件职责

### `backend/app/embedding/openai_provider.py`

新增 `OpenAIEmbeddingProvider`。

职责：

- 调用 OpenAI-compatible `/embeddings` API。
- 从 `settings.embedding_api_key` 和 `settings.embedding_base_url` 读取配置。
- 使用 `settings.embedding_model` 选择 embedding 模型。
- 返回 `list[list[float]]`。
- 处理 HTTP 错误、网络错误、JSON 解析错误和响应格式错误。

## 3. Mock 和真实 Provider 切换方式

### Mock 模式

适合无 API Key 的本地开发：

```env
EMBEDDING_PROVIDER=mock
EMBEDDING_MODEL=mock-embedding
EMBEDDING_DIMENSION=16
```

特点：

- 不调用外部 API。
- 向量稳定可重复。
- 适合验证工程链路。
- 不代表真实语义检索质量。

### 真实 Embedding 模式

适合验证真实 RAG 效果：

```env
EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSION=1536
EMBEDDING_TIMEOUT_SECONDS=60
EMBEDDING_API_KEY=你的 Embedding API Key
EMBEDDING_BASE_URL=https://api.openai.com/v1
```

如果 `EMBEDDING_API_KEY` 或 `EMBEDDING_BASE_URL` 未设置，后端会回退使用：

```env
OPENAI_API_KEY
OPENAI_BASE_URL
```

切换后需要重启后端。

## 4. 重新索引流程

真实 embedding 接入后，旧 mock 索引不应继续用于评估 RAG 质量。

推荐流程：

1. 修改 `backend/.env`：

```env
EMBEDDING_PROVIDER=openai
```

2. 填写真实 embedding model、API Key 和 base URL。
3. 重启后端。
4. 重新上传文件。
5. 等待自动解析、切块、向量化和索引保存。
6. 在聊天框中基于该文件提问。

原因：

- mock vector 没有语义含义。
- 真实 embedding 维度通常与 mock 的 16 维不同。
- VectorStore 会保存新的 `embedding_model` 和实际 `embedding_dimension`。

## 5. RAG 检索质量如何改善

v1.0 前：

```text
query -> mock query vector -> mock chunk vectors -> 工程可跑，但语义质量有限
```

v1.0 后：

```text
query -> real query embedding -> real chunk embeddings -> 更接近语义相关 chunks
```

预期改善：

- 同义问题更容易命中相关 chunk。
- 长文档中相关片段排序更合理。
- RagService 获得的上下文质量更高。
- LLM 回答更有依据。

仍然没有解决：

- 多文件检索。
- rerank。
- query rewrite。
- semantic chunk。
- 数据库持久化。

## 6. API Key 安全机制

当前安全规则：

- 真实 API Key 只写入 `backend/.env`。
- `backend/.env` 被 Git 忽略。
- `.env.example` 只放空值和示例。
- 前端不读取 API Key。
- Provider 不硬编码 API Key。
- 后端统一通过 `settings` 读取配置。

分享项目前应确认：

```text
git check-ignore -v backend/.env
git check-ignore -v backend/uploads/
git check-ignore -v backend/vector_store/
git check-ignore -v .claude/
```

## 8. 当前剩余问题

- 当前真实 embedding provider 尚未在本报告中绑定某个具体服务商的真实 Key。
- 本地 JSON VectorStore 仍不适合生产级数据规模。
- 前端状态刷新后仍不可恢复。
- 当前只支持最近一个 indexed 文件的单文件 RAG。
- 当前没有自动化测试目录，主要依赖编译检查和手动联调。
- TestClient 依赖曾出现 Starlette/httpx 弃用提示，后续测试体系整理时应处理。
