# v1.6.3 Anonymous Client Isolation Report

## 1. 工程效果

本阶段解决公网试用时所有访问者共享历史记录的问题。

实现后，每个浏览器会拥有一个匿名 `client_id`。前端会在所有业务 API 请求中携带：

```text
X-Beichen-Client-Id: <anonymous-client-id>
```

后端按 `client_id` 隔离文件、会话和消息记录。

## 2. 修改文件职责

- `backend/app/core/client_context.py`：读取并校验 `X-Beichen-Client-Id`。
- `backend/app/core/errors.py`：新增 `ClientIdError`。
- `backend/app/db/models.py`：`files` 和 `chat_sessions` 新增 `client_id`。
- `backend/app/db/init_db.py`：为旧 SQLite 文件提供轻量 client_id 列兼容。
- `backend/app/repositories/file_repository.py`：文件读写全部增加 `client_id` 条件。
- `backend/app/repositories/chat_repository.py`：会话和消息读写全部按会话所属 `client_id` 隔离。
- `backend/app/services/file_service.py`：上传、列表、删除文件时传递 `client_id`。
- `backend/app/services/document_parser_service.py`：解析前校验文件属于当前 client。
- `backend/app/services/chunk_service.py`：切块状态只更新当前 client 的文件。
- `backend/app/services/embedding_service.py`：向量化状态只更新当前 client 的文件。
- `backend/app/services/vector_store_service.py`：保存和读取索引前校验文件归属。
- `backend/app/services/retrieval_service.py`：检索时传递 `client_id`。
- `backend/app/services/rag_service.py`：RAG 问答检索时传递 `client_id`。
- `backend/app/services/conversation_service.py`：会话、消息、自动标题、上下文和文件绑定全部按 `client_id` 校验。
- `backend/app/api/v1/files.py`：文件 API 从 header 读取 `client_id`。
- `backend/app/api/v1/chat.py`：聊天和会话 API 从 header 读取 `client_id`。
- `frontend/src/api/clientIdentity.ts`：生成和保存匿名客户端 ID。
- `frontend/src/api/http.ts`：统一为业务请求附加 `X-Beichen-Client-Id`。

## 3. 邀请码和 client_id 的边界

邀请码用于判断访问者能不能进入应用。

`client_id` 用于判断文件、会话和消息属于哪个匿名客户端。

因此，邀请码不是用户身份，`client_id` 也不是正式认证凭证。本阶段仍不是注册登录系统，只适合可信小范围试用。

## 4. 文件隔离调用链

```text
Frontend
-> fetchWithAccess()
-> X-Beichen-Client-Id
-> FastAPI files API
-> get_client_id()
-> FileService / DocumentParserService / ChunkService / EmbeddingService / VectorStoreService
-> FileRepository(file_id + client_id)
-> SQLite files
```

## 5. 会话隔离调用链

```text
Frontend
-> chatApi
-> fetchWithAccess()
-> X-Beichen-Client-Id
-> FastAPI chat API
-> ConversationService
-> ChatRepository(session_id + client_id)
-> SQLite chat_sessions / chat_messages
```

## 6. RAG 问答隔离调用链

```text
POST /api/v1/files/{file_id}/ask
-> get_client_id()
-> ConversationService.ask_file_and_persist(..., client_id)
-> RagService.ask_file(..., client_id)
-> RetrievalService.retrieve(..., client_id)
-> VectorStoreService.load_file_vectors(file_id, client_id)
-> FileRepository.get_file(file_id, client_id)
-> LLMProvider
-> ChatRepository.create_message(session_id, client_id, ...)
```

效果：

- A 用户不能基于 B 用户的文件提问。
- A 用户不能绑定 B 用户的文件到自己的会话。
- A 用户看不到 B 用户的 RAG 引用历史。

## 7. 旧数据清空方案

部署 v1.6.3 后，建议清空旧共享历史记录。

先备份：

```bash
mkdir -p /opt/beichen-agent/backups/v1.6.3-before-isolation
cp -r /opt/beichen-agent/runtime/data /opt/beichen-agent/backups/v1.6.3-before-isolation/
cp -r /opt/beichen-agent/runtime/uploads /opt/beichen-agent/backups/v1.6.3-before-isolation/
cp -r /opt/beichen-agent/runtime/vector_store /opt/beichen-agent/backups/v1.6.3-before-isolation/
```

再清空：

```bash
systemctl stop beichen-agent
rm -f /opt/beichen-agent/runtime/data/beichen.db
rm -f /opt/beichen-agent/runtime/uploads/*
rm -f /opt/beichen-agent/runtime/vector_store/*
systemctl start beichen-agent
```

不要删除 `/opt/beichen-agent/runtime/backend.env`。

## 9. 剩余风险

- `client_id` 存在浏览器 localStorage，清理浏览器数据后会生成新的匿名身份。
- `client_id` 可以被技术用户伪造，因此它不是安全认证。
- 多设备之间不会同步历史。
- 当前仍适合可信小范围试用，不适合开放注册或公测。
- 正式多用户产品仍需要 Auth/User 模块。
