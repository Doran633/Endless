## 7. VectorStore 风险

`backend/vector_store/` 是高风险目录。

原因：

- JSON 索引中保存了：
  - `file_id`
  - `chunk_id`
  - `chunk_index`
  - `content`
  - `embedding`
  - `embedding_model`
- 其中 `content` 是文档原文 chunk。

这意味着：

```text
vector_store 不只是向量，也包含可读原文。
```

当前状态：

- 已被 `.gitignore` 忽略。
- 未被 Git 跟踪。

发布建议：

- 绝不能提交 `backend/vector_store/`。
- 不能把它放进公开压缩包。
- 如果要分享演示数据，应单独制作脱敏样例索引，而不是使用真实本地索引。

## 12. 如果已经误提交敏感文件，应如何处理

如果未来发现真实 API Key、上传文件、数据库或 vector_store 已经提交：

1. 立即停止继续 push。
2. 立即在服务商控制台禁用或轮换泄露的 API Key。
3. 不要只删除当前文件后重新提交，因为 Git 历史仍然保留敏感内容。
4. 使用专门工具清理历史，例如：
   - `git filter-repo`
   - BFG Repo-Cleaner
5. 清理后强制推送前，应确认没有其他协作者依赖旧历史。
6. 如果已经推送到 GitHub，应视为密钥已经泄露。

对 API Key 的判断原则：

```text
只要真实 Key 进入过远端 GitHub，就应该轮换。
```

## 13. GitHub 发布前操作清单

发布前建议依次执行：

```powershell
git status --short --ignored
```

确认敏感目录是 `!!` ignored，而不是 `??` untracked。

```powershell
git ls-files backend/.env backend/uploads backend/vector_store backend/data .claude
```

确认没有输出。

```powershell
git grep -n -E "sk-[A-Za-z0-9_-]{10,}|Bearer [A-Za-z0-9._-]{20,}"
```

确认没有真实密钥。

```powershell
git log --all --oneline -G"sk-[A-Za-z0-9_-]{10,}|Bearer [A-Za-z0-9._-]{20,}"
```

确认历史里没有真实密钥痕迹。

手动检查：

- README 是否准确。
- `.env.example` 是否没有真实 Key。
- docs 是否没有复制真实 Key。
- 不把本地压缩包提交。
- 不把数据库、上传文件、vector_store 作为示例数据上传。
