# v1.4.1 Windows Local Scripts 实现报告

## 1. 工程效果

本阶段完成 Windows 本地试运行脚本整理。

新增三个脚本：

- `scripts/check-local.ps1`
- `scripts/start-local.ps1`
- `scripts/stop-local.ps1`

目标不是新增 AI 功能，而是降低本地运行和排查问题的成本。

完成后，项目从“手动记命令启动前后端”推进到：

```text
先检查环境
再启动服务
出问题时按固定端口停止旧进程
```

## 2. 每个脚本职责

### `scripts/check-local.ps1`

职责：

- 检查 Python 是否可用。
- 检查 Node.js 是否可用。
- 检查 npm 是否可用。
- 检查 `backend/.env` 是否存在。
- 检查 `backend/requirements.txt` 是否存在。
- 检查 `frontend/package.json` 是否存在。
- 检查后端端口 `8000` 是否被占用。
- 检查前端端口 `5173` 是否被占用。

设计原因：

- 让启动失败前先暴露环境问题。
- 非技术用户看到 `[OK]`、`[WARN]`、`[FAIL]` 更容易判断下一步。
- 不读取或输出真实 API Key。
- 脚本输出使用英文 ASCII，避免 Windows PowerShell 默认编码导致中文字符串解析失败。

### `scripts/start-local.ps1`

职责：

- 提示先运行 `check-local.ps1`。
- 检查 Python 和 npm 是否可用。
- 检查 `backend/.env` 是否存在。
- 检查固定端口 `8000` 和 `5173` 是否已被占用。
- 启动 FastAPI 后端。
- 启动 Vite 前端。
- 输出本机访问地址和健康检查地址。

设计原因：

- 固定端口可以减少访问地址混乱。
- 前后端分别打开 PowerShell 窗口，便于观察日志。
- 如果端口已被占用，脚本会要求先运行停止脚本，而不是强行覆盖。

### `scripts/stop-local.ps1`

职责：

- 查找监听 `8000` 的进程。
- 查找监听 `5173` 的进程。
- 只停止这些固定端口对应的进程。
- 不按进程名批量结束所有 `python` 或 `node`。

设计原因：

- 避免误伤其他正在运行的 Python / Node 项目。
- 解决旧进程占用端口、页面没有更新、Vite 端口冲突等问题。

## 3. 启动流程

推荐流程：

```powershell
scripts\check-local.ps1
scripts\start-local.ps1
```

启动成功后访问：

```text
http://127.0.0.1:5173/
```

后端健康检查：

```text
http://127.0.0.1:8000/health
```

## 4. 停止流程

推荐流程：

```powershell
scripts\stop-local.ps1
```

停止脚本会分别检查：

- `8000`
- `5173`

如果端口没有监听进程，会输出 `[OK]`。

如果端口存在监听进程，会输出对应 PID 并停止。

## 5. 端口清理策略

固定端口：

- 后端：`8000`
- 前端：`5173`

策略：

- 只查找 `127.0.0.1` 上固定端口的 `LISTEN` 进程。
- 不查找所有 Python。
- 不查找所有 Node。
- 不删除文件。
- 不清空数据库。
- 不清空 uploads。
- 不清空 vector_store。

这样可以在解决端口占用的同时，降低误操作风险。

## 6. 对非技术用户的帮助

v1.4.1 不能让非技术用户完全零配置，但可以降低启动难度。

帮助包括：

- 不需要记住完整 uvicorn 命令。
- 不需要记住完整 Vite 启动命令。
- 不需要手动查端口 PID。
- 遇到端口占用时，有明确停止脚本。
- 启动后能看到明确访问地址。

仍然需要用户或开发者处理：

- 安装 Python。
- 安装 Node.js。
- 安装依赖。
- 配置 `backend/.env`。
- 准备有效 API Key。

## 7. 安全边界

本阶段没有修改：

- AI 聊天逻辑。
- RAG 主链路。
- Embedding。
- VectorStore。
- Retrieval。
- 数据库结构。
- 前端 UI。

脚本不会：

- 删除 `backend/uploads/`。
- 删除 `backend/vector_store/`。
- 删除 `backend/data/`。
- 输出真实 API Key。
- 批量结束所有 Python / Node 进程。
