# v1.7.5 Semi-Automated VPS Deploy 报告

## 1. 本阶段目标

v1.7.5 不新增 AI 业务功能，不修改 RAG 主链路，也不修改数据库结构。

本阶段目标是把服务器更新流程从多条手动命令整理成一条可审查、可重复执行的半自动部署脚本，降低漏步骤和误操作风险。

## 2. 新增文件职责

### `deploy/scripts/deploy-vps.sh.example`

Ubuntu VPS 半自动部署脚本模板。

职责：

- 检查服务器目录、依赖命令和 Git 状态。
- 默认执行 runtime 备份。
- 拉取 GitHub `main` 分支。
- 安装后端依赖。
- 运行后端 `compileall`。
- 安装前端依赖。
- 运行前端生产构建。
- 发布 `frontend/dist` 到 `/opt/beichen-agent/frontend_dist`。
- 重启 `beichen-agent` systemd 服务。
- 检查 `/health` 和 `/health/config`。
- 检查并 reload Nginx。

脚本不做：

- 不提交代码。
- 不打印 API Key。
- 不打印真实邀请码。
- 不修改生产 `.env`。
- 不删除 runtime 数据。
- 不删除 backups。
- 不修改数据库结构。
- 不做 Docker / GitHub Actions / webhook。

## 4. 半自动部署流程

本地开发机：

```powershell
git status
git add .
git commit -m "your message"
git push origin main
```

VPS：

```bash
ssh root@your-server-ip
cd /opt/beichen-agent/app
sudo bash deploy/scripts/deploy-vps.sh.example
```

脚本内部流程：

```text
preflight
-> backup runtime
-> git fetch / pull
-> backend pip install
-> backend compileall
-> frontend npm ci / npm install
-> frontend build
-> publish frontend_dist
-> restart backend
-> health checks
-> nginx -t
-> reload nginx
```

## 5. 默认备份策略

默认执行：

```bash
bash deploy/scripts/backup-runtime.sh.example
```

备份范围：

- `/opt/beichen-agent/runtime/data`
- `/opt/beichen-agent/runtime/uploads`
- `/opt/beichen-agent/runtime/vector_store`

可选包含日志：

```bash
sudo bash deploy/scripts/deploy-vps.sh.example --include-logs
```

如明确不需要备份，可使用：

```bash
sudo bash deploy/scripts/deploy-vps.sh.example --skip-backup
```

不建议在真实用户已经产生数据后频繁跳过备份。

## 6. 失败处理方式

脚本使用：

```bash
set -euo pipefail
```

含义是任一关键步骤失败就立刻停止。

主要失败点：

- Git 工作区不干净：停止，避免覆盖服务器本地改动。
- GitHub 拉取失败：停止，避免使用半新半旧代码。
- 后端依赖安装或编译失败：停止，不重启后端。
- 前端安装或 build 失败：停止，不发布新的前端产物。
- 后端重启失败：停止，提示查看 systemd / journalctl。
- `/health` 或 `/health/config` 失败：停止，说明后端没有正常服务。
- `nginx -t` 失败：停止，不 reload Nginx。

前端发布采用临时目录：

```text
/opt/beichen-agent/frontend_dist.new
```

只有 build 成功后才替换正式目录，避免 build 失败时破坏当前线上前端。

## 7. 与完整 CI/CD 的区别

当前脚本是半自动部署，不是完整 CI/CD。

它解决：

- 减少重复手敲命令。
- 避免忘记 build / restart / health check。
- 默认部署前备份 runtime。
- 失败时停在明确位置。
- 保留人工确认。

它不解决：

- 自动监听 GitHub push。
- 自动运行远端 CI。
- 自动发布到多台服务器。
- 零停机部署。
- 多环境蓝绿发布。
- 容器隔离。

对于当前 1-5 人可信试用，这是更合适的复杂度。

## 8. 当前限制

- 脚本主要面向 Ubuntu VPS。
- 需要服务器已有 `/opt/beichen-agent` 标准目录结构。
- 需要后端 systemd 服务名为 `beichen-agent`。
- 需要前端由 Nginx 托管 `/opt/beichen-agent/frontend_dist`。
- 需要 GitHub 仓库已经能被服务器拉取。
- 本地 Windows 不能完整验证 systemd / Nginx 部分，需要在 VPS 上实测。

## 9. 验证结果

本阶段已执行：

```powershell
cd backend
python -m compileall app
python -m pytest

cd ../frontend
npm exec tsc -- --noEmit
```

结果：

- `python -m compileall app` 通过。
- `python -m pytest` 通过，12 个测试全部通过。
- `npm exec tsc -- --noEmit` 通过。
- `git diff --check` 通过。
- `git status --short` 仅包含 v1.7.5 脚本和文档改动。

补充说明：

- 本机 Windows 环境的 `bash -n deploy/scripts/deploy-vps.sh.example` 由于 `C:\Windows\System32\bash.exe` / WSL 权限问题返回 `E_ACCESSDENIED`，未能在本机完成 bash 语法检查。
- 该脚本面向 Ubuntu VPS，仍需要在 VPS 上执行 `bash -n deploy/scripts/deploy-vps.sh.example` 或直接进行一次低风险部署实测。
- pytest 当前仍有 FastAPI / Starlette 相关弃用 warning，属于既有测试环境提示，不影响本阶段验证。
