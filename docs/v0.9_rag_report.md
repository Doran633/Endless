# v0.9.0 RAG 文件问答实现报告

## 1. 本次工程效果

v0.9.0 完成了最小单文件 RAG 问答闭环。

现在 indexed 文件可以执行：

```text
用户问题
  -> 本地 VectorStore 检索 top_k chunks
  -> RagService 组装 RAG prompt
  -> 调用现有 LLMProvider
  -> 返回文件问答答案和引用 chunks
```

本阶段仍然保持 MVP 范围：

- 不引入数据库。
- 不引入 pgvector。
- 不实现多文件问答。
- 不实现 Agent。
- 不实现企业权限。
- 不实现复杂 prompt 管理系统。

## 2. 修改文件职责

### `backend/app/services/rag_service.py`

新增 `RagService`。

职责：

- 接收 `file_id`、`query`、`top_k`。
- 调用 `RetrievalService.retrieve()` 获取相关 chunks。
- 组装最小 RAG prompt。
- 调用现有 `LLMService` / `LLMProvider`。
- 返回 answer、used_chunks、provider、model 和 usage。

设计原因：

- RetrievalService 只负责检索，不调用 LLM。
- RagService 负责编排“检索 + 生成”。
- LLMProvider 继续隔离具体模型调用。

### `backend/app/api/v1/files.py`

新增：

```text
POST /api/v1/files/{file_id}/ask
```

职责：

- 接收文件问答请求。
- 调用 `RagService.ask_file()`。
- 使用统一 `ok()` 响应格式返回结果。

### `backend/app/schemas/file.py`

新增：

- `AskFileRequest`
- `AskFileResponse`

职责：

- 约束文件问答请求参数。
- 明确后端返回 answer、used_chunks、provider、model 和 token usage。

### `backend/app/core/errors.py`

新增：

- `RagError`

职责：

- 为 RAG 问答阶段提供稳定的业务错误类型。
- 避免把空问题、无检索结果等错误混在通用异常中。

### `frontend/src/api/fileApi.ts`

新增：

- `askFile(fileId, query, topK)`

职责：

- 调用 `/api/v1/files/{file_id}/ask`。
- 保持前端 API 调用集中在 file API client 中。

### `frontend/src/types/index.ts`

新增：

- `AskFileResponse`

职责：

- 与后端 AskFileResponse 对齐。
- 支持前端展示 answer、used_chunks、model 和 provider。

### `frontend/src/components/FileCenter.tsx`

新增文件问答入口和弹窗。

职责：

- indexed 文件展示可用的“问答”入口。
- 输入 query 和 top_k。
- 调用 `askFile()`。
- 展示 AI 回答。
- 展示引用 chunks 和 score。

## 3. 完整调用链路

```text
Frontend FileCenter
  -> askFile(fileId, query, topK)
  -> POST /api/v1/files/{file_id}/ask
  -> files.py ask_file()
  -> RagService.ask_file()
  -> RetrievalService.retrieve()
  -> VectorStoreService.load_file_vectors()
  -> EmbeddingService / MockEmbeddingProvider 生成 query vector
  -> cosine similarity 排序 top_k chunks
  -> RagService._build_prompt()
  -> LLMService.chat()
  -> MockLLMProvider 或 OpenAIProvider
  -> AskFileResponse
  -> Frontend 展示 answer + used_chunks
```

## 4. 数据流说明

输入：

```json
{
  "query": "这个文件主要讲了什么？",
  "top_k": 3
}
```

后端处理：

1. `files.py` 接收请求。
2. `RagService` 清理 query。
3. `RetrievalService` 从本地 JSON VectorStore 中检索相关 chunks。
4. `RagService` 把 query 和 chunks 组装成 prompt。
5. `LLMService` 根据 `.env` 选择 mock 或 openai provider。
6. LLM 返回自然语言答案。

输出：

```json
{
  "file_id": "xxx",
  "query": "这个文件主要讲了什么？",
  "answer": "根据文档内容，...",
  "top_k": 3,
  "used_chunk_count": 3,
  "used_chunks": [],
  "provider": "openai",
  "model": "deepseek-v4-flash",
  "usage": {
    "input_tokens": 123,
    "output_tokens": 456
  }
}
```

## 5. 当前限制

- 当前 embedding 仍是 mock embedding，检索质量不能代表真实语义检索效果。
- 当前只支持单文件问答，不支持多文件知识库。
- 文件元数据和前端文件列表尚未数据库持久化。
- RAG prompt 仍是内置简单模板，没有独立 prompt 管理。
- 当前没有引用高亮和答案可信度校验。
- 当前没有流式输出，长答案需要等待完整响应。
